## Open your till

Open [app.vendurepos.com](https://app.vendurepos.com). On **Sign in to Vendure**,
choose **Email and password** or **Device key**.
Use one browser tab per till: a second tab is told the till is open in another tab.

When you sign in with email and password, the till sends them from this browser to the store URL you entered.
It then saves the session in this browser's `localStorage`: the store URL, channel token, barcode field, your email,
the store's settings and the session token the store returned. It never saves the password. With a device key, it saves the key itself.
Signing out deletes that saved session and, for a password sign-in, asks the store to end the session.
The catalogue and the sales not yet sent to your store are kept in SQLite databases inside this browser.
Signing out deletes the catalogue but never the sales database, so unsent sales wait for your next sign-in.
Every request in the till's code goes to that store URL, except on the public demo at demo.vendurepos.com:
it posts anonymous demo events to ph.wcpos.com with no cookie and nothing stored. The events are `demo_opened`, `demo_signed_in`, `demo_sale_completed` and `demo_reset`, each with a random id that lasts one page load and the demo's host name, plus the referring site on `demo_opened`; ph.wcpos.com is a self-hosted PostHog analytics server, the same one this website's page-view counter reports to. The page loads scripts only from its own host, cannot be shown inside another site, and may connect to any `https://` address.

The till's source is [MIT-licensed](https://github.com/vendurepos/app) and builds to static files. Building it yourself needs your own RxDB Premium
licence token in `RXDB_PREMIUM`; then run `pnpm build:web` in `apps/pos` and serve `apps/pos/dist` from your own host.
Your store must then allow that origin in its CORS settings, the same way it allows `https://app.vendurepos.com`.

## Enter your store details

Enter the store URL; a trailing `/admin-api` is accepted.
Enter the channel token. For staff sign-in it is optional: blank means the default channel.

For **Barcode field (optional)**, enter the name of an existing single text
`ProductVariant` custom field, such as `barcode`, to use for scanning. Leave it blank to turn this off.
The barcode field is set when signing in; **Settings** shows the field you chose.

## Sign in with a staff account

Choose **Email and password** and sign in as a Vendure administrator who can read
the channel's catalogue and settings and has `TallyPosSell` (plugin 0.2.0+) or `CreateOrder`.

### Give each cashier their own account

Each cashier signs in to the till with their own Vendure administrator account, and **Hand over** switches between them without closing the register.

1. Use the `vendurepos-pos-till` role that **New POS till key** creates (plugin 0.2.0+), or in the Vendure Dashboard
   create a role in the till's channel with `TallyPosSell`, `ReadCatalog`, `ReadSettings`, `ReadCustomer`, `CreateCustomer`
   and `ReadOrder`. The till's order list needs `ReadOrder`, which that role gains only in the plugin release after 0.3.0;
   until then, add it to the role yourself.
2. Create one administrator per cashier, with only that role.
3. Each cashier signs in with **Email and password**; the till names them by their email. At the end of a shift,
   [**Hand over**](/docs/at-the-till#check-the-register-during-the-day) signs them out and the next cashier signs in.

Refunding at the till will need `TallyPosRefund`, given separately, once the plugin release after 0.3.0 is out.

## Create and use a device key

You need plugin 0.2.0 or later and Vendure's React Dashboard.
See [Plugin setup](/docs/plugin-setup) for installation.

1. Add `'api-key'` to `authOptions.tokenMethod`:

   ```ts
   tokenMethod: ['bearer', 'cookie', 'api-key'],
   ```

2. In the Dashboard, switch to the till's channel first. A key works only in the
   channel it was created in, and the dialog names that channel.
3. Go to **System → API keys → New POS till key** and name the key after the device.
   This creates or extends the `vendurepos-pos-till` role with `TallyPosSell` and
   the reads a till needs, creates the key with that role and shows the key once.
4. On the till, choose **Device key**, paste the key and the till's channel token, and sign in.

The till shows the key's name on receipts as `Till: <name>`.
Rotate or delete a key on its own page in the Dashboard.
Signing out forgets the key on that device; it does not revoke it.
A till whose key is revoked asks for a new one and keeps its cart.

## Make the key button available in a pnpm project

For pnpm projects, the Dashboard build does not find the button unless its Vite
plugin points at your `node_modules`:

```ts
vendureDashboardPlugin({
  // ...your existing options
  pluginPackageScanner: {
    nodeModulesRoot: path.resolve(__dirname, 'node_modules')
  },
}),
```

npm projects need nothing extra.
