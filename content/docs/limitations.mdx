- Pre-release: expect changes before 1.0.

- Web till only for now. Its browser tests run in desktop Chrome; other browsers are not tested yet.

- Building the till yourself needs your own RxDB Premium
  licence token in `RXDB_PREMIUM`.

- On plugin 0.3.0, refunds go through the Vendure Dashboard, and Vendure keeps a refund
  of a POS order Pending until an administrator settles it with the Admin API's [`settleRefund`](/docs/at-the-till#settle-a-dashboard-refund) mutation.
  The live demo refunds at the till.

- Coupon codes: not yet.
  Line and order discounts work at the till.

- Card payments are taken on a separate terminal and confirmed on the till.
  The till does not talk to the terminal.

- Receipts and reports print through the browser's print dialog, on any printer that device's browser can use.
  The till does not connect to a receipt printer directly and does not open a cash drawer.

- Prices and stock: an open till picks up a price change within about a minute
  and a stock change within about five minutes.

- Sales take stock through Vendure's stock allocation strategy,
  from the channel's stock locations. The till cannot pick a location for a sale.

- One browser tab per till.

- Private browser windows that give a site no storage,
  such as Safari's, cannot run the till.

- Sales not yet sent are kept only in this browser. If this site's data is cleared, or the device is lost,
  while the header still shows **N orders waiting to send**, those sales are lost.

- The manager's approval on register close is a typed name,
  not a verified sign-in.

- Postgres only.
  MySQL, MariaDB and SQLite are not supported.

- Device keys need plugin 0.2.0 or later;
  see [Plugin setup](/docs/plugin-setup).
