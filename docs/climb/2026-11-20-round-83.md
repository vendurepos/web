## Worst defect per judge and criterion

### C1 First impression (mean 8.6)
- J1 (8): The first thing above the headline is the badge "Pre-release · plugin 0.3.0", which shows a plugin version before the page has said a plugin exists. Further down, the home page's "Setting up the store" column hands a newcomer raw jargon: "Node ^20.19 || >=22.12" and "RxDB Premium licence token (RXDB_PREMIUM)". _[home.desktop.01 (badge), home.desktop.02 / home.phone.04-05 (Before you start)]_
- J2 (8): The home page's 'Before you start' list mixes server jargon into what should be a shop owner's checklist: 'Node ^20.19 || >=22.12' and 'RxDB Premium licence token (RXDB_PREMIUM)' sit next to the counter items, so a non-developer reading on a phone can't tell which lines are theirs and which are the freelancer's. _[home.desktop.02 / home.phone.03, 'Before you start' → 'Setting up the store']_
- J3 (10): none found _[text/home.txt; shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (8): On phone, the hero till screenshot is a narrow view showing only two product cards and a category chip row clipped at "Gif"; the cart (3, €20.09) is collapsed into a tab, so the promised sale in progress is not visible. _[home.phone.01]_
- J5 (9): The footer drops two sibling brands, 'Built with TallyUI. For Medusa, see MedusaPOS.', and the till's analytics go to 'ph.wcpos.com'. Nothing on the page says how VendurePOS, TallyUI, MedusaPOS and WCPOS relate or who is behind them, so a first-time visitor cannot tell whether this is one person's side project or a product family. _[home.desktop.02 footer; home.desktop.02 'Live demo or your own store' table, last row]_

### C2 Credibility (mean 8.4)
- J1 (8): The home page calls the till MIT-licensed open source, then says self-hosting needs "your own RxDB Premium licence token (RXDB_PREMIUM)". It never explains what RxDB Premium is or what it costs, and never says whether app.vendurepos.com is free. A first-timer reads that as a hidden catch. A smaller point: demo usage events go to "ph.wcpos.com", a domain from a different brand that the page never explains. _[home.desktop.02 'Setting up the store' last bullet and comparison table last row; text/home.txt]_
- J2 (9): The site is honest about limits, but the refund caveat is written for a developer. The comparison table says 'No, not on plugin 0.3.0: refund in the Vendure Dashboard. The refund stays Pending until an administrator settles it with two Admin API calls', which a shop owner can't act on and which reads as a hidden catch. _[home.desktop.02, 'Live demo or your own store' table, refund row]_
- J3 (9): The homepage cites an acceptance run and a 200-send test, but its evidence links target mutable main-branch test source rather than a versioned run result. _[text/home.txt, 'What it does today'; tech.json, home.desktop.links]_
- J4 (9): The home comparison table says the demo sends "anonymous usage events to ph.wcpos.com". A wcpos domain appears on vendurepos.com with no explanation of what it is or why it is there. _[home.desktop.02 (Live demo or your own store table)]_
- J5 (7): The headline promise is 'open-source till … MIT licensed', but 'To build and host it yourself … you need your own RxDB Premium licence token (RXDB_PREMIUM)'. That is a paid third-party licence, and its price and terms are never stated. In practice the only free path is the hosted app.vendurepos.com, and nowhere does the site say who operates it, whether it stays free, or what support or uptime comes with it. The changelog adds to the doubt: three plugin releases in five days (2026-10-01 to 10-06), then none for six weeks. _[home.desktop.02 'Setting up the store' last bullet; limitations.desktop.01 'Setting up the store'; changelog.desktop.01]_

### C3 Path to a till (mean 8.0)
- J1 (8): Step 3 has the reader write and run two scratch files (src/generate-migration.ts, src/run-migrations.ts). ## Overall worst defect per judge

- **J1 First-time visitor** (C2): A first-time visitor never learns what VendurePOS costs. The home page says "open-source" and "MIT licensed", but its only money-related line is that self-hosting needs "your own RxDB Premium licence token (RXDB_PREMIUM)", with no word on whether the hosted app.vendurepos.com is free. That reads as a hidden catch exactly when the visitor is deciding whether to stay. _[home.desktop.02 / home.phone.04-05, 'Before you start' > 'Setting up the store', last bullet]_ Fix: Add one plain sentence near the hero or in Before you start saying whether the hosted till at app.vendurepos.com is free to use (and needs no licence). Move the RxDB Premium self-host note to Connect a till with a short explanation of what RxDB Premium is.
- **J2 Working shop owner** (C2): On the shop's own Vendure store, plugin 0.3.0 can't refund at the till. The home comparison table explains this as 'The refund stays Pending until an administrator settles it with two Admin API calls; see Plugin setup', developer language a shop owner can't act on. The cashier workaround (Dashboard refund, Pay out, terminal refund) is only on At the till. _[home.desktop.02, 'Live demo or your own store' table, 'Refund a sale at the till' row]_ Fix: In that cell, give the counter steps in plain words: 'Manager refunds in the Vendure Dashboard, the cashier records a Pay out, refund the card on the terminal.' Link to At the till#refund-a-sale and move the Admin API settle detail to Plugin setup only.
- **J3 Developer evaluating it** (C3): A developer maintaining channels with both tax-inclusive and tax-exclusive pricing must guess how to choose the single store-wide order tax strategy. _[Quick start §6, 'Why these pairings', in text/endpoint_llms_full_txt.txt; shots/quick-start.desktop.03.jpg]_ Fix: State the supported configuration or explicit limitation for mixed pricing modes. Include the expected rounding behavior and a concrete sale-total verification for each mode.
- **J4 Designer** (C6): Inline code pills are overused in running prose. Config and permission names ("APP_ENV", "CORS_ORIGINS", "apiOptions", "vendure-config.ts"; TallyPosSell, ReadCatalog, ReadSettings, ReadCustomer, CreateCustomer, ReadOrder…) render as bordered, padded pills that stack up in a paragraph, break its even line height and make the docs look noisy, worst on phone. _[quick-start.phone.05; connect-a-till.desktop.01]_ Fix: Move permission sets and config names out of sentences into a bulleted list or small table, defined once and linked from the other pages. Give inline code in prose a lighter style (monospace with a faint tint, no border, minimal padding) so it sits on the text line without changing line height.
- **J5 Competitor-aware sceptic** (C2): 'Open-source, MIT licensed' is the lead claim. Yet self-hosting the till needs a paid RxDB Premium licence of unstated cost, which leaves the hosted app.vendurepos.com as the real free path, and the site never says who runs it, whether it stays free, or where to get support. A client weighing this against Square or Shopify POS cannot assess vendor risk. The six-week gap since the last plugin release (2026-10-06) makes that worse. _[home.desktop.02 'Setting up the store'; limitations.desktop.01; changelog.desktop.01]_ Fix: Next to the RXDB_PREMIUM line, add one short paragraph: who operates app.vendurepos.com, that it is free (and for how long), what RxDB Premium costs if you self-host, and where to file issues or get help.
