## Worst defect per judge and criterion

### C1 First impression (mean 8.6)
- J1 (8): The first feature card says sales not yet sent "are lost if this site's data is cleared". Read on vendurepos.com, "this site" sounds like the marketing site, not the till app at app.vendurepos.com, so the one caveat a newcomer reads first is ambiguous. _[home.desktop.01 / home.phone.02, card 'Keeps selling offline']_
- J2 (8): On the phone the home header shows only 'Docs' and 'Live demo' plus search and a chevron, so 'At the till' (the page my staff need) is two taps away. The hero line 'Your own store needs the plugin on your Vendure server first' speaks to my developer, not to me. _[home.phone.01; home.desktop.01 hero]_
- J3 (10): none found _[text/home.txt; shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (9): The phone top bar shows only "VendurePOS  Docs  Live demo" plus search and a chevron. "Quick start", the main next step, is missing from the bar and only reachable through the hero button or the menu. _[home.phone.01]_
- J5 (8): The hero lede says what it is and who it is for, but that it has two parts (a hosted till at app.vendurepos.com plus a server plugin you install) is left to the small grey line under the buttons, "Your own store needs the plugin on your Vendure server first", so in five seconds a buyer cannot tell whether this is a hosted service or a self-installed plugin. _[home.desktop.01 (line under Live demo / Quick start); home.phone.01]_

### C2 Credibility (mean 8.4)
- J1 (7): The home page sells the product as "open-source" and "MIT licensed", then in 'Before you start' says that self-hosting needs "your own RxDB Premium licence token (RXDB_PREMIUM)". It never says what RxDB Premium is or that it costs money, so it reads like a paid catch tucked behind jargon. _[home.desktop.02 / home.phone.04, 'Setting up the store' last bullet]_
- J2 (9): The home 'Live demo or your own store' table lists 'Refund a sale at the till', with Yes for the demo and No for my store on plugin 0.3.0. The phone hero shows the till on a phone, yet Limitations says 'tablets, phones and iPad not tested'. _[home.desktop.02 comparison table; home.phone.01 vs limitations]_
- J3 (10): none found _[text/home.txt; text/limitations.txt; text/connect-a-till.txt]_
- J4 (9): The comparison table's demo row says "anonymous usage events to ph.wcpos.com". The unexplained wcpos domain breaks the otherwise single-brand voice. _[home.desktop.02 (comparison table)]_
- J5 (7): The site never says who builds and maintains VendurePOS, where to report a bug or get help, or on what terms app.vendurepos.com is hosted (free? for how long? any uptime promise?). The footer only offers "MIT licensed. Built with TallyUI. For Medusa, see MedusaPOS." plus GitHub and npm, so a sceptic cannot judge bus factor or support. Smaller points: the live demo runs ahead of the released plugin ("Refund a sale at the till: Yes" on the demo, "No, not on plugin 0.3.0" on your store; the customer note is demo-only). The ReadOrder gap in the role made by New POS till key has gone unpatched since 2026-10-06 and is worked around on four pages. ## Overall worst defect per judge

- **J1 First-time visitor** (C2): A first-time visitor is told the product is open source and MIT licensed, then meets an unexplained "RxDB Premium licence token (RXDB_PREMIUM)" requirement in 'Before you start'. With no word on what it is, whether it costs money, or that the hosted app.vendurepos.com needs none, it plants doubt about the 'free and open' promise. _[home.desktop.02 / home.phone.04, 'Setting up the store' last bullet]_ Fix: Say it in plain words, for example: "Using app.vendurepos.com needs nothing extra. Building the till yourself needs a paid RxDB Premium licence (a third-party database add-on); see Connect a till."
- **J2 Working shop owner** (C4): The 'At the till' guide is the page I would hand my two staff, and it mixes live-demo-only features into the steps for a real store on plugin 0.3.0: 'On the live demo, type a Customer note…' and a whole 'Refund at the till (live demo only)' section with 'Refund steps on the live demo'. Staff who practise on the demo learn a till refund and a customer note that our shop will not have. _[at-the-till.desktop.01-03]_ Fix: Take the demo-only items out of the cashier steps and put them in one clearly labelled 'Only on the live demo' box at the end of the page, or move them to the home comparison table, so the page my staff read describes only what our till does.
- **J3 Developer evaluating it** (C3): A developer with tax-inclusive and tax-exclusive channels must guess which global order-tax strategy to use. _[Quick start, step 6, 'Why these pairings'; text/endpoint_llms_full_txt.txt:850–872]_ Fix: Document the supported configuration for mixed-mode channels and how to verify rounding in each channel. If that combination is unsupported, state the restriction explicitly before the configuration example.
- **J4 Designer** (C5): The at-the-till screenshots render at three different widths (~836 / 418 / 545 px). Two of them appear as a small card inside a larger padded outer frame, so the page looks assembled from three different components. _[at-the-till.desktop.02, at-the-till.desktop.03, at-the-till.desktop.04]_ Fix: Give every docs screenshot one width (the content column, or one fixed max width, centred) and a single frame with no inner padding. Captions should keep the same alignment and spacing under each image.
- **J5 Competitor-aware sceptic** (C2): Nowhere on the site says who maintains VendurePOS, where to file issues or get support, or the terms of the hosted till at app.vendurepos.com (cost, longevity, no SLA). A sceptic advising a client cannot rule out a one-person side project that may vanish, and the honest limits elsewhere do not make up for that. _[home.desktop.02 / home.phone.05 footer ('MIT licensed. Built with TallyUI. For Medusa, see MedusaPOS.' + GitHub, npm, Limitations, Changelog); docs Overview 'Next steps']_ Fix: Add one short 'Who runs this' paragraph to the Overview and a footer link. It should name the maintainer, link GitHub Issues for bugs and support, and state that app.vendurepos.com is a free static build of the MIT source with no uptime guarantee and that you can self-host it (Connect a till).
