## Overall worst defect per judge

- **J1 First-time visitor** (C2): A first-time visitor cannot find out what it costs. Home says the source is MIT licensed, but self-hosting needs 'your own RxDB Premium licence token', and nothing says whether the hosted till at app.vendurepos.com is free, paid or free only during pre-release. The licence note reads like a catch the site is not explaining. _[home/desktop/02 'Setting up the store' (text/home.txt line 86); no page states pricing]_ Fix: Add one plain line near the hero or in 'Before you start' stating whether app.vendurepos.com is free to use (and for how long), and that RxDB Premium is a paid licence that only people building the till themselves need.
- **J2 Working shop owner** (C4): When something goes wrong at the counter, Troubleshooting hands the shop owner developer material ('copy the refused line from this till's sync log, and match its errorCode', a collapsed sync-log how-to, GraphQL tallyNeedsAdminCommands) instead of a short 'what staff do now, what to tell your developer' answer. _[troubleshooting.desktop.01 / troubleshooting.phone.01, section 'When till updates need attention']_ Fix: Open that section with a two-line 'At the counter' box (keep selling, keep the printed Z report, tell your developer the code shown) and move errorCode matching and the GraphQL calls under a 'For your developer' sub-heading.
- **J3 Developer evaluating it** (C3): A developer with both tax-inclusive and tax-exclusive channels must still infer the store-wide tax strategy despite following the quick start. _[Quick start step 6, 'Why these pairings'; text/endpoint_llms_full_txt.txt; shots/quick-start.desktop.03.jpg]_ Fix: Add a short mixed-channel example specifying the supported strategy and expected rounding behavior, with a verification sale in each pricing mode. If that configuration is unsupported, state the limitation explicitly.
- **J4 Designer** (C6): Quick-start code blocks soft-wrap mid-expression on phone ("generateMigration(config, { name:" / "'AddVendurePos', outputDir:"), making the copy-paste setup code look broken on the page a developer follows step by step _[quick-start.phone.03, quick-start.phone.06]_ Fix: Turn off soft-wrap on code blocks below 640 px and let them scroll horizontally, or hand-break the snippets into short lines (one argument per line) so they read cleanly at 390 px
- **J5 Competitor-aware sceptic** (C2): The site never says who builds or supports VendurePOS, or whether any real store runs it. The analytics go to ph.wcpos.com with no explanation, and there has been no plugin release since 0.3.0 on 2026-10-06. A sceptic comparing it with Shopify POS or Square cannot judge the bus factor. _[home.desktop footer; changelog.desktop.01]_ Fix: Add a short 'Who maintains this' block on home and Overview. Name the maintainer or organisation and how it relates to WCPOS/TallyUI, link a support or issues channel, give the release cadence, and list any pilot stores (or say plainly that there are none yet).
