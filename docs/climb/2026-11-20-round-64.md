## Worst defect per judge and criterion

### C1 First impression (mean 8.4)
- J1 (8): The hero is clear, but below it the home page turns into server-admin detail a newcomer cannot parse. The 'Before you start > Setting up the store' column shows 'Node ^20.19 || >=22.12' and 'your own RxDB Premium licence token (RXDB_PREMIUM)', and the comparison table's refund row says 'settles it with two Admin API calls'. _[home.desktop.02 'Before you start' and 'Live demo or your own store' table; home.phone.04]_
- J2 (8): The home 'Before you start' block mixes my counter questions with developer requirements, so a shop owner reads 'Node ^20.19 || >=22.12' and 'RXDB_PREMIUM' right next to 'one tab per till'. On a phone, the hero screenshot is cropped to the product grid ('Gif' cut off), and the cart and checkout never show. _[home.desktop.02 'Before you start'; home.phone.01 hero screenshot]_
- J3 (10): none found _[shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (8): Above the fold there are three stacked text blocks before the product image: a 4-line centred lede that spends a clause explaining Vendure to Vendure developers ('open-source software for running an online shop'), the CTA pair, then a second 2-line grey note ('Your own store needs the plugin on your Vendure server first...'). The hero reads as prose, not a headline plus action, and the lede ends on a short widow line 'connection drops.' _[home.desktop.01 (hero, y≈260-500); home.phone.01]_
- J5 (8): The hero says what it is and who it is for, but nothing on the first screen says whether the hosted till at app.vendurepos.com is free, needs an account, or who runs it, so a buyer comparing it with Square or Shopify POS cannot tell the cost model in five seconds. _[home/desktop/01 hero ("VendurePOS is an open-source till for Vendure..." and the Live demo / Quick start buttons)]_

### C2 Credibility (mean 8.2)
- J1 (8): The home table says the demo's only traffic is 'anonymous usage events to ph.wcpos.com, with no cookie'. A visitor who has never heard of wcpos sees an unexplained domain from another brand right where the page is trying to reassure them. Only Connect a till explains that it is a self-hosted PostHog server. _[home.desktop.02 table row 'Sales reach Vendure, once each, even offline'; home.phone.04]_
- J2 (8): The proof behind the two headline claims ('Read the acceptance test', 'Read the 200-send test') links to raw test source files on GitHub (offline.spec.ts, replay.e2e.ts). A non-developer gets code, not a readable result such as a dated run or a pass record. _[home.desktop.01 'Keeps selling offline' / 'Every sale lands once' cards]_
- J3 (9): The offline and replay proof links point to moving main-branch test files without identifying the successful run or tested revision behind the claims. _[text/home.txt, 'What it does today'; tech.json, home.desktop.links]_
- J4 (9): The hero pill says 'Pre-release · plugin 0.3.0', but the till app actually served at app.vendurepos.com is version 0.1.0. Only the changelog says so ('till app version 0.1.0, built 20 Nov 2026'), so the one version badge on the home page describes the server package, not the product a visitor will open. _[home.desktop.01 pill vs changelog.desktop.01 second paragraph]_
- J5 (7): "MIT licensed" and "open-source till" are undercut by "To build and host it yourself ... you need your own RxDB Premium licence token (RXDB_PREMIUM)". The site never says this is a paid third-party licence or what it costs, and nowhere names who is behind the project or app.vendurepos.com (the only hint is analytics going to ph.wcpos.com), so in practice you are tied to an unnamed operator's hosted build. _[home/desktop/02 'Before you start > Setting up the store' last bullet; connect-a-till/desktop/01 'Where your data goes'; limitations 'Setting up the store']_

## Overall worst defect per judge

- **J1 First-time visitor** (C1): A first-time visitor scrolling past the clear hero reaches deployment detail meant for the person installing the plugin: Node semver ranges, an RXDB_PREMIUM licence token, Admin API refund settling and an unexplained ph.wcpos.com. The home page reads as harder and more caveated than the product is. _[home.desktop.02 'Live demo or your own store' table and 'Before you start'; home.phone.04-05]_ Fix: Replace the 'Setting up the store' column with one line ('Needs a Vendure 3.6+ store on Postgres; the quick start covers the rest') and move the Node, RxDB and Admin API details to the quick start and Limitations. Name ph.wcpos.com as 'our own analytics server' where it appears.
- **J2 Working shop owner** (C4): The page my staff are sent to when the till shows a sync warning is half written for whoever runs the Vendure server (errorCode lists, needs_admin GraphQL mutations, LAN http CSP options). The counter action ('leave the app open, don't reload, keep selling, keep the printed Z report') is buried among server instructions. _[troubleshooting.desktop.01-03 / troubleshooting.phone.01-07]_ Fix: Open Troubleshooting with a short 'At the counter' list: each header notice and the one thing a cashier does. Move the errorCode list, the GraphQL resolve steps and the LAN http note under a clearly labelled 'For whoever runs your Vendure server' section, or onto Plugin setup.
- **J3 Developer evaluating it** (C3): The tax-strategy instructions leave developers with mixed inclusive/exclusive channels to determine the supported store-wide configuration themselves. _[Quick start, section 6, 'Why these pairings'; text/endpoint_llms_full_txt.txt]_ Fix: State whether mixed pricing modes are supported. Provide the supported strategy and a concrete totals-verification example, or explicitly identify this configuration as unsupported.
- **J4 Designer** (C5): The home page's main proof section, 'What it does today', mixes two bordered cards (unequal body lengths, leaving a dead band in the right card above 'Read the 200-send test') with eight unboxed text pairs in the same grid, so the section that sells the product reads as two unrelated layouts stitched together. _[home.desktop.01 bottom to home.desktop.02 top (also home.desktop-dark, home.phone.02)]_ Fix: Give the two proof cards a distinct full-width treatment (a 2-up band with matched heights and the test link as a text link at the card foot), then set the eight features as a clearly separate 2-column list under its own small subheading, e.g. 'Also at the till'.
- **J5 Competitor-aware sceptic** (C2): The site sells an 'open-source, MIT licensed' till, but self-hosting needs an RxDB Premium licence the site never says is paid, and the hosted alternative at app.vendurepos.com has no named operator, price or continuity promise. A sceptic advising a client cannot tell whether they are adopting open source or depending on an anonymous hosted service, so I would warn them off. _[home/desktop/02 'Setting up the store' last bullet; connect-a-till/desktop/01 'Where your data goes']_ Fix: Add one plain sentence beside the RXDB_PREMIUM note: who runs app.vendurepos.com and that it is free, that RxDB Premium is a paid commercial licence from RxDB (with a link to its pricing), and what happens to tills if the hosted build goes away (it is static files you can host yourself with that licence).
