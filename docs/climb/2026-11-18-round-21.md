## Worst defect per judge and criterion

### C1 First impression (mean 8.6)
- J1 (8): The hero is clear, but the feature cards right below it use point-of-sale and engineering jargon with no plain gloss: 'close it with a Z report', 'Open a register with a counted float', 'Keyboard-wedge scanners', 'records it in one transaction with an idempotency ledger'. A visitor who half knows Vendure stalls on these in the first scroll. _[home desktop slice 01 ('What it does today' cards); home phone slices 02-03]_
- J2 (9): The hero "Point of sale for Vendure" with the real till screenshot and "Live demo" button lands at once, but nothing above the fold tells an owner it suits a counter with staff and a card terminal; that only comes later ("Card payments are taken on a separate terminal" is on Limitations). _[home.desktop.01 / home.phone.01]_
- J3 (10): none found _[shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (8): On a 390 px phone the home header shows only the wordmark, a search icon and an unlabelled chevron, so the hero's 'Docs' and 'Connect your store' entry points from the desktop nav are hidden. The desktop hero screenshot is also cut through a half-row of product tiles at its bottom edge. _[home/phone/01 (header); home/desktop/01 (hero image bottom edge)]_
- J5 (8): The home page says what it is ('Point of sale for Vendure', 'Pre-release · plugin 0.3.0') but never says who it is for, who should not use it, or how it differs from Shopify POS, Square or the Vendure admin. A sceptic comparing tills gets no 'not for you if…' line. _[home.desktop.01-02 (hero and 'What it does today'); no such section on any page]_

### C2 Credibility (mean 8.0)
- J1 (8): The home page never says who makes VendurePOS or whether the hosted app at app.vendurepos.com is free. The only clue to the maker is an unexplained third-party domain in the demo table: 'All it sends is anonymous usage events to ph.wcpos.com'. The page doesn't say what wcpos.com is until Connect a till. _[home desktop slice 02 (comparison table, last row) and footer ('MIT licensed. Built with TallyUI.')]_
- J2 (8): The honest "Live demo or your own store" table says the till sends "anonymous usage events to ph.wcpos.com", a domain from another brand that is never explained, so an owner wonders who gets their shop's data. _[home.desktop.02 / home.phone.04]_
- J3 (9): The 25-sale acceptance and 200-send claims link to test source on main, without a dated passing run tied to the advertised plugin 0.3.0. _[text/home.txt, What it does today; tech.json, home.desktop.links]_
- J4 (8): The payment-screen screenshot used to show the real till has a cart line called 'Tally Fixture Mug', which reads as test-fixture data in what should look like a real sale. _[at-the-till/desktop/02 (image 'The payment screen on the live demo till', first cart line)]_
- J5 (7): 'MIT licensed' is repeated in the home footer and on Overview, but 'Before you start' and Limitations also require an 'RxDB Premium licence token (RXDB_PREMIUM)' to build or self-host the till. The site never says what that licence costs, or that the open-source build depends on it. No maintainer, company or support channel is named, and the changelog shows nothing shipped since 0.3.0 on 2026-10-06. _[home.desktop.02 'Before you start' + footer; limitations; changelog]_

## Overall worst defect per judge

- **J1 First-time visitor** (C1): Someone arriving from a 'Vendure point of sale' search meets unexplained trade and engineering jargon in the first feature cards ('Z report', 'counted float', 'Keyboard-wedge scanners', 'idempotency ledger'). So the part that should sell the product in a minute reads as written for people who already run a till. _[home desktop slice 01 / home phone slices 02-03, 'What it does today' cards]_ Fix: Add a few plain words to each term in the cards, e.g. 'Z report (end-of-day cash summary)', 'opening float (the cash in the drawer at the start)', 'USB barcode scanners', and replace 'idempotency ledger' with 'a record of every sale id it has seen'.
- **J2 Working shop owner** (C4): On a real store the till cannot refund: "Vendure keeps the refund Pending until an administrator settles it with the Admin API's settleRefund mutation". This is in developer terms with no plain step for the owner, and the live demo refunds at the till, so the demo hides the gap. _[at-the-till.desktop.02 "Refund a sale"; limitations.phone.01]_ Fix: Start "Refund a sale" with one plain line: "On your own store, cashiers can't refund yet. Your developer or store admin refunds the order in the Vendure Dashboard and settles it (see Plugin setup > Settle a Dashboard refund)." Say the same in the home table's refund row.
- **J3 Developer evaluating it** (C4): A rejected register update blocks later till updates, yet the troubleshooting instructions end at inspecting or copying the sync log without explaining how the store owner proceeds. _[shots/troubleshooting.desktop.01.jpg, Act on a header notice, Till updates line; text/troubleshooting.txt]_ Fix: Document the supported recovery procedure, or explicitly state that this case requires maintainer assistance and link the escalation destination. Specify which log details to provide and how to preserve the queued records while awaiting help.
- **J4 Designer** (C3): Run commands in the quick start's migration step sit inline in prose ('npx tsx src/generate-migration.ts', 'npx tsx src/run-migrations.ts') and break mid-token across lines on both desktop and phone. The one step most likely to fail has no copyable terminal block, while step 1 has one. _[quick-start/desktop/01 (step 3, y≈1437–1528); quick-start/phone/02–03]_ Fix: Put the two npx tsx commands in Terminal code blocks with copy buttons, as in step 1. Give short inline code `white-space: nowrap` (or break only at '/') so pills never split at a hyphen.
- **J5 Competitor-aware sceptic** (C2): The site sells itself as 'MIT licensed' open source, but building or self-hosting the till needs a paid 'RxDB Premium licence token (RXDB_PREMIUM)'. The site never says what that costs, who it is bought from, or that hosted use avoids it. With no named maintainer or support channel and no release in six weeks, a sceptic would warn a client off on the licence point alone. _[home.desktop.02 'Before you start' + home footer 'MIT licensed'; limitations]_ Fix: Next to 'Before you start' and in Limitations, add one plain paragraph: what RxDB Premium is, what it costs, that it is needed only to build or self-host and not to use app.vendurepos.com, and whether an open fallback is planned. Add a 'Who maintains this / where to get help' line to the footer.
