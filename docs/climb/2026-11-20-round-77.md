- J2 (9): Hero subline is pitched at my developer, not me: it says the till needs a 'plugin on your Vendure server' before it says what my staff can do at the counter. Otherwise the hero is clear and specific, with the 'Pre-release · plugin 0.3.0' badge, Live demo and Quick start. _[home.desktop.01 / home.phone.01 hero]_
- J3 (10): none found _[shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_

## Overall worst defect per judge

- **J1 First-time visitor** (C1): After a clear hero, the home page's comparison table and 'Before you start' block are written for a Vendure server admin, not a first-time visitor. A newcomer reads "settles it with two Admin API calls", "Node ^20.19 || >=22.12", "RxDB Premium licence token (RXDB_PREMIUM)" and "ph.wcpos.com" and concludes the product is not for them yet. _[home.desktop.02 / home.phone.04-05]_ Fix: On the home page, shorten the refund cell to "Not yet: refund in the Vendure Dashboard" and say in a few words who ph.wcpos.com is. Move the Node range and the RXDB_PREMIUM self-host note to Overview or Plugin setup, keeping a one-line "Needs Vendure 3.6+ on Postgres" here.
- **J2 Working shop owner** (C3): Refunds on plugin 0.3.0: the till cannot refund, and a Dashboard refund 'stays Pending' until an administrator settles it. 'Refund a sale' sends me to 'Plugin setup has the steps for them' and gives me no plain action of my own, so a customer return at the counter has no clear owner-side answer. _[at-the-till.desktop.03 'Refund a sale'; home.desktop.02 comparison table refund row]_ Fix: Open 'Refund a sale' with a three-line owner box: record a Pay out for cash or refund on the card terminal now, then send the developer this copyable message to settle the Pending refund.
- **J3 Developer evaluating it** (C3): A developer whose Vendure store mixes tax-inclusive and tax-exclusive channels must guess how to satisfy the conflicting tax-strategy recommendations. _[text/endpoint_llms_full_txt.txt, Quick start, step 6, 'Why these pairings']_ Fix: State the supported configuration for mixed pricing modes, or explicitly state that this configuration is unsupported. Include the expected tax-total checks for both channel modes and explain the effect on the existing web shop.
- **J4 Designer** (C3): Quick start's 'Check it worked' only lists text conditions ('the payment is tally-pos, settled; … tallySaleAt custom field is set') on a ~10.5k px page with no images, so a first-time integrator has no picture of what success looks like _[quick-start.desktop.04 / quick-start.phone.08]_ Fix: Under 'Check it worked', add one captioned screenshot of the Vendure Dashboard order (tally-pos payment Settled, fulfilment shown) and one of the till header in its synced state, sized to read on a 390 px phone
- **J5 Competitor-aware sceptic** (C2): The site never says who builds or supports VendurePOS (the footer only says "MIT licensed. Built with TallyUI."). The plugin has not shipped since 0.3.0 on 2026-10-06, and a known ReadOrder role bug is documented ("Not in the release notes…") instead of fixed. A sceptic advising a client on a till that handles money cannot judge support or longevity, so they would steer the client to Shopify POS or Square. _[changelog.desktop.01; home footer; home.desktop.01]_ Fix: Add a short 'Who builds this' line on home and the docs Overview: maintainer or company, release cadence, issue tracker and support channel. Then ship a plugin patch that adds ReadOrder to the device-key role, or state when it lands.
