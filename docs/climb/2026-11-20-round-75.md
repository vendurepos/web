## Worst defect per judge and criterion

### C1 First impression (mean 8.6)
- J1 (8): The hero is clear, but the first feature a newcomer reads, 'Keeps selling offline', spends most of its six lines on caveats and test details ('a reload needs the connection, and clearing that browser's data for the till loses them. Our acceptance run makes 25 sales, 20 of them offline...'), and the next card's button reads 'Read the 200-send test'. Below the fold it reads like an engineering report, not a pitch. _[home.desktop.01 'What it does today' cards; home.phone.02]_
- J2 (8): Hero line calls Vendure 'the open-source headless commerce framework', which is developer jargon to a shop owner. On the phone the hero till image shows only two product tiles and the category chips are cut off mid-word ('Gif'). _[home.phone.01 hero]_
- J3 (10): none found _[shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (8): The hero puts two centred body blocks around the buttons: a 4-line centred lede that ends on the short line 'connection drops.', then a second smaller centred note under the CTAs ('Your own store needs the plugin on your Vendure server first: ...'). That gives three text tiers before the screenshot and slows the five-second read. _[home.desktop.01 (hero) and home.phone.01]_
- J5 (9): The only maturity signal in the hero is the badge 'Pre-release · plugin 0.3.0', which cites the server plugin's version; the till a shop actually uses is 'till app version 0.1.0' (stated only on the Changelog), so the badge makes it look further along than the app is. _[home/desktop/01 badge vs changelog/desktop/01 second paragraph]_

### C2 Credibility (mean 8.2)
- J1 (8): The demo row on the home page says 'All it sends is anonymous usage events to ph.wcpos.com, with no cookie'. The page never says what wcpos.com is or why a VendurePOS demo reports to it; only Connect a till explains that it is a self-hosted PostHog server. To a stranger, an unexplained third-party domain looks like something being hidden. _[home.desktop.02 'Live demo or your own store' table, last row; home.phone.04]_
- J2 (8): The refund row says refunds 'stay Pending until an administrator settles it with two Admin API calls; see Plugin setup'. That is honest, but it sends a non-developer owner to a developer page for a routine counter task, and it does not say plainly that each refund needs the freelance developer. _[home live-demo vs own-store table, Refund row; at-the-till Refund a sale]_
- J3 (10): none found _[text/home.txt; text/limitations.txt; text/connect-a-till.txt]_
- J4 (8): The refund caveat is repeated almost word for word in three places on the home page alone: the table row 'No, not on plugin 0.3.0: refund in the Vendure Dashboard. The refund stays Pending until an administrator settles it with two Admin API calls', the 'Before you start' bullet, and again in Limitations. The fourth line of the table row makes that cell the tallest on the page, so a plain limit reads as a hedge. _[home.desktop.02 (Live demo or your own store table, 'Refund a sale at the till' row)]_
- J5 (7): The site never says who builds or maintains VendurePOS, whether any shop runs it in production, or where to get support. The footer ('Built with TallyUI. For Medusa, see MedusaPOS') and the home table's 'anonymous usage events to ph.wcpos.com' point to a wider organisation that is never named. The table titled 'This is what it shows today' also leaves out one demo-only feature: At the till says 'On plugin 0.3.0, Order details has no customer note. On the live demo, type a Customer note'. _[home/desktop/02 'Live demo or your own store' table and footer; at-the-till.txt 'Order details']_

## Overall worst defect per judge

- **J1 First-time visitor** (C1): Past the hero, a first-time visitor who only half knows Vendure gets caveat-first engineering prose: the opening feature card is mostly about data loss on reload and acceptance-run counts, a button says 'Read the 200-send test', and 'Before you start' exposes 'Node ^20.19 || >=22.12' and an 'RxDB Premium licence token (RXDB_PREMIUM)'. The visitor learns the limits before the benefits and leaves unsure whether this is for them. _[home.desktop.01 'What it does today'; home.desktop.02 'Before you start']_ Fix: Cut each feature card to one plain benefit sentence, with the caveats behind a 'limits' link and the test links renamed (for example 'See the proof'). Move the Node range and the RXDB_PREMIUM self-hosting note from the home page into the quick start.
- **J2 Working shop owner** (C2): On the owner's own store, plugin 0.3.0 cannot finish a refund. The refund 'stays Pending until an administrator settles it with two Admin API calls', and those calls are documented only on the developer-facing Plugin setup page. Two staff at a counter cannot complete a routine refund without phoning the freelance developer. _[home own-store table Refund row; at-the-till Refund a sale; plugin-setup 'Settle a Dashboard refund']_ Fix: Under At the till › Refund a sale, add a boxed 'Your developer must do this once per refund' note. Include the exact copy-paste settleRefund call, or a Dashboard route if one exists. Say the same in plain words on the home Refund row, so the owner knows before installing.
- **J3 Developer evaluating it** (C3): A developer with both tax-inclusive and tax-exclusive channels must guess how to satisfy the conflicting recommendations for the single store-wide tax strategy. _[shots/quick-start.desktop.03.jpg, step 6; text/endpoint_llms_full_txt.txt, Why these pairings]_ Fix: State whether mixed-pricing channels are supported. If supported, give the exact strategy configuration and a verification example for each pricing mode; otherwise state the restriction explicitly.
- **J4 Designer** (C5): The home page's main feature section mixes two component styles: two bordered proof cards, the right one with a bottom-aligned button and a dead gap above it, followed by eight loose unbordered blocks. The page's most important section looks unfinished next to an otherwise disciplined layout. _[home.desktop.01 'What it does today' (and the same in home.desktop-dark.jpg)]_ Fix: Put the button directly after the text in each proof card (stop stretching it to the bottom), or make the two cards one full-width proof band. Give the eight features a single shared treatment: a 2-column grid with hairline dividers or a light card, all the same.
- **J5 Competitor-aware sceptic** (C2): A sceptic advising a client cannot find out who stands behind VendurePOS: no maintainer or company is named, there is no support channel beyond a GitHub footer link, and nothing says whether any shop runs it in production. Meanwhile the site hints at an unexplained parent ('ph.wcpos.com', TallyUI, MedusaPOS), which looks like a side project spread across several platforms. _[home/desktop/02 table row 'Sales reach Vendure...' and footer]_ Fix: Add a two-line 'Who builds it' block above the home footer. It should name the maintainer or company and its link to WCPOS/TallyUI, say where to report issues or get help, and state plainly how many production shops run it (even 'none yet').
