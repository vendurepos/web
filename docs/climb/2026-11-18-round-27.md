## Worst defect per judge and criterion

### C1 First impression (mean 8.8)
- J1 (9): The hero never says where your own till runs or whether it costs anything: app.vendurepos.com is first mentioned in the fifth 'Before you start' bullet ('To build and host it yourself instead of using app.vendurepos.com...'), so a newcomer only finds out there is a hosted app near the bottom of the page. _[home/desktop/02 'Before you start' bullet 5; home/phone/05]_
- J2 (8): The home page speaks to the developer before the owner. It opens with 'headless commerce framework', and 'Before you start' asks for an 'RxDB Premium licence token (RXDB_PREMIUM)' and a 'keyboard-wedge' scanner. The page the owner actually needs, 'At the till', is linked only from the bottom of the page. _[home.desktop.01-03, home.phone.02-04]_
- J3 (10): none found _[text/home.txt; shots/home.desktop.01.jpg]_
- J4 (9): The hero till screenshot cuts through a half-visible fourth row of product tiles, so the image ends mid-row under the caption _[home.desktop.01]_
- J5 (8): The hero says what it is and gives two clear CTAs, but nothing on the home page says who it suits and who should not use it, for example a single-store shop already on Vendure+Postgres versus a multi-store retailer who needs a hardware till, a drawer kick or terminal integration. Today a buyer has to piece that together from the 'Before you start' bullets and Limitations. _[home.desktop.01 hero; home.desktop.02 'Before you start']_

### C2 Credibility (mean 8.6)
- J1 (8): The home page says 'The till's source is MIT licensed. To build and host it yourself ... you need your own RxDB Premium licence token (RXDB_PREMIUM)' without saying what RxDB Premium is or that it is a paid third-party licence, so next to 'MIT licensed' it reads like a hidden catch. The demo row's unexplained 'ph.wcpos.com' (a different brand's domain) adds to the question of who is behind this. _[home/desktop/02 'Before you start' bullet 5 and comparison table last row; home/phone/04-05]_
- J2 (9): The payment screenshot shows a test-fixture product called 'Tally Fixture Mug'. In a guide written for counter staff it reads as test data. The limits themselves are stated very honestly: no refunds at the till, no card-terminal link, unsent sales lost if site data is cleared. _[at-the-till.desktop.02 (payment screen image)]_
- J3 (10): none found _[text/home.txt; text/limitations.txt; text/connect-a-till.txt]_
- J4 (9): 'Before you start' repeats the refund and coupon limits already given in the comparison table row 'Refund a sale at the till', which adds length but no new information _[home.desktop.02]_
- J5 (7): The site never says who builds and maintains VendurePOS, who runs app.vendurepos.com (the origin every till loads from), whether the hosted app is free or for how long, or where to report a bug or get support. The only hint of an operator is the unexplained third-party analytics host 'ph.wcpos.com'. _[home.desktop.02 footer ('MIT licensed. Built with TallyUI.'), connect-a-till.desktop.01 'Where requests go']_

### C3 Path to a till (mean 7.8)
- J1 (8): Step 5 says 'Add https://app.vendurepos.com to the scaffold's CORS_ORIGINS allowlist' without naming the file (.env) or saying that this variable exists only in @vendure/create projects. A developer who did not scaffold has to guess, and is pointed to the object form only after that. _[quick-start/desktop/02 '5. Allow the POS origin through CORS'; quick-start/phone/05]_
- J2 (7): Whether staff can sell tomorrow depends on a developer finishing about seven server steps: migration, bearer tokenMethod, CORS, tax strategy, channel stock. A known gotcha is passed on to the reader: 'On plugin 0.3.0 the role it creates (vendurepos-pos-till) has the step 4 permissions except ReadOrder, so add ReadOrder to that role yourself'. _[quick-start.desktop.03-05, 'Optional: a device key']_
- J3 (8): The tax instructions prescribe different store-wide strategies for inclusive and exclusive channels, but tell mixed-pricing stores only to 'account for the store-wide strategy', leaving the configuration decision unresolved. _[text/endpoint_llms_full_txt.txt, Quick start step 6, 'Why these pairings']_
- J4 (8): Step 5 says to add the origin to 'the scaffold's CORS_ORIGINS allowlist' but does not say which file or env var holds it _[quick-start.desktop.02]_
- J5 (8): The role that the plugin's own 'New POS till key' button creates is missing a permission the till needs. The docs patch around this known 0.3.0 defect three times ('On plugin 0.3.0 the role it creates (vendurepos-pos-till) has the step 4 permissions except ReadOrder, so add ReadOrder to that role yourself') instead of the plugin fixing it. A first-time installer who follows the device-key path and skims past it gets 'order history is refused'. _[quick-start.desktop.04 'Optional: a device key for each till'; connect-a-till text 'Give each cashier their own account' and 'Create and use a device key']_

## Overall worst defect per judge

- **J1 First-time visitor** (C2): A first-time visitor reading 'MIT licensed' then meets 'you need your own RxDB Premium licence token (RXDB_PREMIUM)' with no word on what that is or what it costs. Nothing on the home page says whether the hosted app.vendurepos.com is free to use, so the open-source pitch looks like it may hide a cost. _[home/desktop/02 'Before you start' bullet 5; home/phone/05]_ Fix: In that bullet, add one clause saying RxDB Premium is a paid third-party licence needed only to build the till yourself, and state plainly whether using app.vendurepos.com costs anything.
- **J2 Working shop owner** (C4): Instructions for staff and for the developer are mixed together, so the owner cannot tell which job is theirs. Troubleshooting moves from 'At the counter:' straight into 'For the store owner: ... the refusal is a DEBUG line, Register command result … status=rejected errorCode=…' and errorCode/GraphQL detail. It warns that for any other code 'the till has no retry or skip ... Those closures and cash records do not reach your Vendure store from this till', and gives the owner no plain next step. Refunds, likewise, are handed to 'whoever manages your Vendure store' with no owner-level checklist. _[troubleshooting.desktop.01 'Till updates line'; at-the-till.desktop.02 'Refund a sale']_ Fix: Split each problem into two labelled boxes: 'At the counter (staff)', which says what to tap and what not to do, and 'Send this to your developer', which holds the errorCode, DEBUG and GraphQL detail. Add one short owner checklist for a refund: who does it in the Dashboard, the Pay out for cash, and how to tell when it is settled.
- **J3 Developer evaluating it** (C3): A developer maintaining channels with both tax-inclusive and tax-exclusive pricing must guess how to satisfy the conflicting store-wide tax-strategy recommendations. _[text/endpoint_llms_full_txt.txt, Quick start step 6, 'Why these pairings']_ Fix: Document the supported configuration and expected rounding behavior for mixed-pricing channels. If that configuration is unsupported, state the restriction explicitly before the strategy snippets.
- **J4 Designer** (C5): The desktop docs sidebar lists 'Quick start' twice ('Docs / Live demo / Quick start' group directly above the page list that also starts 'Overview / Quick start'), with 'Docs' styled like a heading. It is the first thing seen on every docs page and makes the navigation look unfinished _[docs.desktop.01, quick-start.desktop.01 and every docs desktop slice]_ Fix: Remove the top 'Docs / Live demo / Quick start' group from the docs sidebar so each page appears once. Move 'Live demo' to an external link at the end of the page list
- **J5 Competitor-aware sceptic** (C2): A buyer cannot tell who stands behind the product. No maintainer, company or support/issue channel is named, and nothing says who runs app.vendurepos.com, the hosted origin every till must load from, or whether it is free or will stay up. The only alternative, self-hosting, needs a paid RxDB Premium licence whose cost is never stated. I would not advise a client to put a shop's tills on that without knowing who to call. _[home.desktop.02 'Before you start' + footer; connect-a-till.desktop.01 'Where your data goes']_ Fix: Add a short 'Who runs this' block on the home page and Overview: the maintainer, who operates app.vendurepos.com and on what terms (free, no SLA, pre-release), a link to GitHub issues for support, and a link to the RxDB Premium pricing for self-hosters.
