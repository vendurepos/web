## Worst defect per judge and criterion

### C1 First impression (mean 8.4)
- J1 (8): The hero is clear, but the first feature card below it, 'Keeps selling offline', spends most of its words on caveats ('a reload needs the connection, and clearing that browser's data for the till loses them'). The rest of 'What it does today' uses terms a newcomer has to stop on: 'a settled payment and a delivered fulfilment', 'keyboard-wedge scanners', 'Z report'. _[home.desktop.01 'What it does today' cards; home.phone.02]_
- J2 (8): Hero leads with "an open-source till for Vendure, the open-source headless commerce framework" and only the small line under the buttons, "Your own store needs the plugin on your Vendure server first", tells an owner that their developer has to install something before staff can sell. _[home.desktop.01 / home.phone.01]_
- J3 (10): none found _[shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (8): The hero carries a four-line centred lede ('VendurePOS is an open-source till for Vendure, the open-source headless commerce framework. It is made for shops ... when the connection drops.') and then a second centred two-line note under the buttons ('Your own store needs the plugin on your Vendure server first...'), so the fold reads as two ragged centred text blocks around the CTAs instead of one sharp line. _[home.desktop.01 (y 255-500); home.phone.01]_
- J5 (8): Home says clearly what it is ("Point of sale for Vendure", "Pre-release · plugin 0.3.0") but never says who should not use it or how it compares with the obvious alternatives (Shopify POS, Square, Lightspeed). A buyer has to piece that together from "Before you start" ("only in desktop Chrome", "No coupon codes and no cash drawer"). _[home/desktop/02-03 ("What it does today", "Before you start"); text/home.txt]_

### C2 Credibility (mean 8.0)
- J1 (7): The home page never says what anything costs. The hosted till at app.vendurepos.com has no price or 'free' statement, and 'Setting up the store' says self-hosting needs 'your own RxDB Premium licence token (RXDB_PREMIUM)' without saying that this is a paid third-party licence. The only visible licensing statement is 'MIT licensed', so 'open-source' reads as possibly hiding a cost. The demo row also names an unexplained third-party domain ('anonymous usage events to ph.wcpos.com'). _[home.desktop.02 'Before you start > Setting up the store' and the 'Live demo or your own store' table; home.phone.04-05]_
- J2 (8): Home table refund row: "The refund stays Pending until an administrator settles it with two Admin API calls; see Plugin setup" is developer jargon that hides what the owner actually has to do; the demo row's "anonymous usage events to ph.wcpos.com" names an unexplained third-party domain. _[home.desktop.02 (Live demo or your own store table)]_
- J3 (9): The 25-sale and 200-send claims link to test source on main, without identifying a passing run or tested commit. _[text/home.txt, 'Keeps selling offline' and 'Every sale lands once'; tech.json, home links]_
- J4 (9): The comparison table says the demo's only outbound traffic is 'anonymous usage events to ph.wcpos.com', a domain from a different product that the page never explains, so a careful reader stops to wonder who wcpos is. _[home.desktop.02 'Sales reach Vendure, once each, even offline' row; home.phone.04]_
- J5 (7): Nothing on the site says who builds or maintains VendurePOS. The footer says only "Built with TallyUI. For Medusa, see MedusaPOS", and the demo telemetry goes to ph.wcpos.com without saying why. The only sign of upkeep is the changelog: the last plugin release is "0.3.0 … 2026-10-06", and it admits "Not in the release notes: in 0.2.0 and 0.3.0 this role has no ReadOrder". That known bug has gone about six weeks without a patch, and the workaround is repeated on four pages. _[changelog/desktop/01; home/desktop footer slice; connect-a-till/desktop/01 ("On plugin 0.3.0 that role has no ReadOrder: add it yourself")]_

## Overall worst defect per judge

- **J1 First-time visitor** (C2): A first-time visitor cannot tell whether VendurePOS costs anything. The home page never says whether the hosted till at app.vendurepos.com is free, and self-hosting the 'MIT licensed' till needs 'your own RxDB Premium licence token' with no word that this is a paid third-party licence. 'Open-source' therefore reads as possibly hiding a cost. _[home.desktop.02 'Before you start > Setting up the store' (also home.phone.04-05)]_ Fix: Add one plain sentence to 'Before you start': what using app.vendurepos.com costs (for example 'free, no account with us'), and that building the till yourself needs a paid RxDB Premium licence from its vendor.
- **J2 Working shop owner** (C3): Refunds on your own store are explained only in developer terms: the till cannot refund on plugin 0.3.0 and the refund "stays Pending until an administrator settles it with two Admin API calls: a query for the refund's ID, then the settleRefund mutation", while At the till's "Refund a sale" just says to ask whoever manages the store, so an owner cannot tell who does what or how long the customer's refund sits Pending. _[home.desktop.02 refund row; limitations.desktop.01; at-the-till.desktop.03 (Refund a sale); plugin-setup.desktop.01 TOC "Settle a Dashboard refund"]_ Fix: In At the till › Refund a sale, add a short plain-language block: who does each step (counter, owner, developer), that the refund shows Pending until settled, and a direct link to Plugin setup › Settle a Dashboard refund labelled "send this to your developer".
- **J3 Developer evaluating it** (C3): A developer maintaining channels with both inclusive and exclusive pricing cannot determine the supported store-wide tax strategy from the setup instructions. _[Quick start, step 6; shots/quick-start.desktop.03.jpg; text/endpoint_llms_full_txt.txt:889–891]_ Fix: Add an explicit mixed-mode recommendation with its rounding consequences and a verification example for each pricing mode. If that configuration is unsupported, state the limitation directly.
- **J4 Designer** (C3): Quick start is the page that turns a visitor into a user, and it runs about 7,000 px of prose and code with no image at all. Step 8's nine UI sub-steps and the 'Check it worked' Dashboard checks have no picture, while At the till, the cashier page, has three screenshots. _[quick-start.desktop.03-04 / quick-start.phone.07-09]_ Fix: Add one captioned screenshot of the 'Sign in to Vendure' form (Email and password tab, store URL and channel token filled) at the top of step 8, and one of the synced order in the Vendure Dashboard (tally-pos payment Settled, fulfilment Delivered) under 'Check it worked'.
- **J5 Competitor-aware sceptic** (C2): A sceptic advising a client cannot judge whether this project will be around in a year. No page says who maintains it, how it is funded, or how it relates to WCPOS/MedusaPOS. The only sign of upkeep is a changelog whose last plugin release is 0.3.0 on 2026-10-06, carrying an admitted, unpatched bug ("in 0.2.0 and 0.3.0 this role has no ReadOrder"). That bug is handed to the user as a manual workaround on four pages. _[changelog/desktop/01; home footer; connect-a-till/desktop/01]_ Fix: Add a two-line "Who builds this / project status" block on home and Overview: the maintainer, the relationship to WCPOS and MedusaPOS, release cadence, and a link to recent commits. Ship 0.3.1 with ReadOrder in the vendurepos-pos-till role so the four workaround notes can go.
