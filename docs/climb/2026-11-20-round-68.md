## Worst defect per judge and criterion

### C1 First impression (mean 8.6)
- J1 (8): The hero is clear, but below the fold the home page turns into a server checklist a first-timer cannot read: 'Node ^20.19 || >=22.12 on the server that runs Vendure', 'RxDB Premium licence token (RXDB_PREMIUM)', 'keyboard-wedge scanners', 'Z report'. Nothing says in one line who the till is for at the counter (shop staff) and who sets it up (a Vendure developer). _[home.desktop.02 'Before you start' / home.phone.04-05]_
- J2 (8): The first explanatory line is written for developers, not shopkeepers: "Vendure, the open-source headless commerce framework"; a shop owner has to work past jargon before reading that it is "made for shops that sell online with Vendure and also sell in person". _[home.desktop.01 / text/home.txt line 12]_
- J3 (10): none found _[text/home.txt; shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (9): Phone hero opens with a ~100px empty band above the "Pre-release · plugin 0.3.0" pill, and the phone header keeps only "Docs" and "Live demo", dropping "Quick start" from the nav _[home.phone.01]_
- J5 (8): Home says who it is for ('made for shops that sell online with Vendure and also sell in person') but never who should not use it or how it compares with Shopify POS, Square or Lightspeed. 'Before you start' lists gaps such as no cash drawer, no coupon codes and only desktop Chrome tested, but never concludes 'if you need X, use Y instead'. Home also never says who maintains the project or where to get support. _[home.desktop.01-02, home.phone.01-05 ('Before you start', footer 'MIT licensed. Built with TallyUI. For Medusa, see MedusaPOS.')]_

### C2 Credibility (mean 8.4)
- J1 (8): The home comparison table says the demo sends 'anonymous usage events to ph.wcpos.com' and does not say what wcpos.com is or how it relates to VendurePOS. Only Connect a till explains it is a self-hosted PostHog server. The home page also never says who builds or maintains the project. _[home.desktop.02 table row 'Sales reach Vendure, once each, even offline' / home.phone.04]_
- J2 (8): The home comparison table answers "Refund a sale at the till" with "Yes" for the demo but "No ... stays Pending until an administrator settles it with two Admin API calls" for your store, so the demo shows a smoother day than a real shop gets; and the till role missing ReadOrder is admitted only as "Not in the release notes" deep in the changelog. _[home.desktop.02 comparison table; changelog.desktop.01 0.2.0 last bullet]_
- J3 (10): none found _[text/home.txt; text/limitations.txt; text/connect-a-till.txt]_
- J4 (9): In the comparison table the "Refund a sale at the till" row's store cell is a 4-line paragraph ("No, not on plugin 0.3.0: … two Admin API calls; see Plugin setup") that buries the key caveat inside a table cell and breaks the scan rhythm of the other one-line cells _[home.desktop.02]_
- J5 (7): The shipped plugin has had no release since 2026-10-06 (0.3.0), and the role it creates is knowingly broken. The changelog admits it: 'Not in the release notes: in 0.2.0 and 0.3.0 this role has no ReadOrder'. Connect a till says 'On plugin 0.3.0 that role has no ReadOrder: add it yourself'. Six weeks on there is no 0.3.1, only workaround notes on four or more pages. The live demo also runs ahead of what a store can install: refund at the till is 'Yes' on the demo but 'No, not on plugin 0.3.0', and the customer note exists only on the demo. A sceptic reads this as a demo that oversells a stalled plugin. _[changelog.desktop.01 / text changelog; connect-a-till text; home 'Live demo or your own store' table; at-the-till text ('On plugin 0.3.0, Order details has no customer note. On the live demo, type a Customer note')]_

### C3 Path to a till (mean 7.8)
- J1 (8): The quick start is complete and ends with a clear 'Check it worked' list. But it opens with a warning box about @vendure/email-plugin and 'one database transaction' before step 1, and step 2 spends a paragraph on why the code is named Tally rather than VendurePOS. A newcomer hits caveats before the first command. _[quick-start.desktop.01 'Before a sale on a live store' and step 2 / quick-start.phone.01-02]_
- J2 (7): Nowhere says plainly what device to put on the counter: Before you start says "tablets and phones, an iPad included, are not tested yet" while the phone home page shows the till running on a phone, and Quick start step 8 "Sign in and make a sale" never names a device, browser or scanner setup. _[home.phone.01 hero image vs text/home.txt line 79; quick-start.desktop.03 step 8]_
- J3 (8): Step 6 recommends different order-tax strategies for inclusive and exclusive channels, but tells stores mixing those modes only to account for the store-wide strategy, leaving the actual configuration unresolved. _[Quick start, step 6; text/endpoint_llms_full_txt.txt:846–875]_
- J4 (8): Quick start has no images at all: step "8. Sign in and make a sale" is a text-only a–i list and "Check it worked" is five bullets, with no picture of the "Sign in to Vendure" form or of the synced order in the Vendure Dashboard, so the reader cannot see what success looks like _[quick-start.desktop.03, quick-start.desktop.04, quick-start.phone.07, quick-start.phone.08]_
- J5 (8): The quick start is complete but long: nine steps with migrations, tokenMethod, CORS, a tax-strategy table and channel/stock prep. A working till still needs manual role surgery ('ReadOrder, or the till sells but its order history is refused'). Refunds made in the Dashboard then need two raw Admin API calls (orders query plus settleRefund). There is no screenshot of the till's sign-in or synced state to confirm success visually. The collapsed legacy note 'If your store already allows vendurepos.vercel.app' adds noise to a first install. _[quick-start.desktop.01-04, quick-start.phone.01-09; plugin-setup text ('Settle a Dashboard refund')]_

## Overall worst defect per judge

- **J1 First-time visitor** (C2): On a site called VendurePOS, the home page's comparison table says the demo sends usage events to 'ph.wcpos.com' and never explains that domain. The home page also never names who makes the project. A first-time visitor from search is left wondering whose product this really is and who is tracking the demo. _[home.desktop.02 comparison table, last row / home.phone.04]_ Fix: In that cell, say what the domain is (for example: 'to our self-hosted PostHog analytics at ph.wcpos.com, run by the WCPOS team that builds VendurePOS'). Add a footer line naming the maintainer next to 'MIT licensed. Built with TallyUI.'
- **J2 Working shop owner** (C3): A shop owner can't find out what to run the till on at the counter: the site says tablets, phones and iPads are untested, yet its phone home page shows the till on a phone, and the setup steps never name a device, browser or scanner arrangement. _[home.phone.01 hero image; text/home.txt "Before you start"; quick-start step 8]_ Fix: Add one "Counter setup" line to Before you start and At the till: for example, a laptop or desktop running Chrome, one tab per till, a USB barcode scanner that types like a keyboard, receipts through the browser print dialog. Caption the phone screenshot "phone layout, not tested yet".
- **J3 Developer evaluating it** (C3): A developer with tax-inclusive and tax-exclusive channels cannot determine the supported store-wide tax strategy from the setup instructions. _[Quick start, step 6 and 'Why these pairings'; text/endpoint_llms_full_txt.txt:846–875]_ Fix: Add an explicit configuration recommendation for mixed pricing modes, or state that this setup is unsupported. Include a small verification example showing the expected till and Vendure totals for each mode.
- **J4 Designer** (C3): Quick start step "8. Sign in and make a sale" and "Check it worked" are text only: no visual of the sign-in screen or of the resulting order in Vendure, so a developer cannot see what success looks like _[quick-start.desktop.03, quick-start.desktop.04]_ Fix: Add a screenshot of the filled "Sign in to Vendure" form under step 8a and one of the synced order (tally-pos payment settled, fulfilment delivered) in the Vendure Dashboard under "Check it worked"
- **J5 Competitor-aware sceptic** (C2): The installable plugin has stalled at 0.3.0 (2026-10-06) with a known defect in its own vendurepos-pos-till role. The changelog says 'Not in the release notes: in 0.2.0 and 0.3.0 this role has no ReadOrder', and connect-a-till says 'that role has no ReadOrder: add it yourself'. Meanwhile the live demo shows refund at the till and a customer note that 0.3.0 cannot do. A competitor-aware buyer sees a demo running ahead of a plugin nobody has patched in six weeks. _[changelog; connect-a-till; quick-start step 8; home 'Live demo or your own store' table; at-the-till]_ Fix: Ship plugin 0.3.1 with ReadOrder added to the till role, then delete the 'add it yourself' workarounds. On home, state the release cadence and maintainer, and when demo-only features (refund at the till, customer note) will reach a published plugin.
