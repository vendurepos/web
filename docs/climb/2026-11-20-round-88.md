## Worst defect per judge and criterion

### C1 First impression (mean 8.4)
- J1 (8): The hero explains Vendure only as "the open-source headless commerce framework", and the badge reads "Pre-release · plugin 0.3.0". A visitor who half knows Vendure gets two terms ("headless", "plugin 0.3.0") with no meaning attached in the first five seconds. _[home desktop slice 01 (hero paragraph and badge); same on home phone 01]_
- J2 (8): The home page's 'Before you start' block mixes the counter needs with developer requirements (Node, Postgres, the RxDB Premium licence token), and the refund row says 'settles it with two Admin API calls'. A non-developer owner hits jargon on the first page they read. _[home.desktop.02 / home.phone.04, 'Before you start' and the 'Live demo or your own store' table]_
- J3 (10): none found _[shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (8): On phone the hero's proof screenshot (till mid-sale) crops to two product cards and the category chip row is cut mid-word at "Gif", so the first phone view undersells the till. _[home.phone.01]_
- J5 (8): The phone hero screenshot is cropped to two product cards, so the cart and checkout (the part that shows it is a real till) never appear above the fold. The home page also never says who should NOT use it (e.g. 'need integrated card payments or an iPad till? use Shopify POS/Square'), so a visitor comparing tills has to piece that together from 'Before you start'. _[home.phone.01; text/home.txt]_

### C2 Credibility (mean 8.6)
- J1 (8): The comparison table says the demo "sends ... anonymous usage events to ph.wcpos.com". The site never says who or what wcpos.com is, so a newcomer sees data going to an unrelated-looking third-party domain. _[home desktop slice 02, 'Live demo or your own store' table, last row; home phone 04]_
- J2 (9): The phone cashier-sheet screenshot shows 'open since 22:07' next to 'Last synced 10:07 PM': 24-hour and 12-hour clocks in the same image. The desktop version (22:06) has no Sync row, so the two shots of one screen disagree. _[at-the-till.phone.07 vs at-the-till.desktop.03]_
- J3 (10): none found _[text/home.txt; text/limitations.txt; text/connect-a-till.txt]_
- J4 (9): None that hurts trust. The honest caveat inside the "Keeps selling offline" card is long for a home-page card, but it reads as candour, not weakness. _[home.desktop.01]_
- J5 (7): No named maintainer, company or support channel anywhere: the footer gives only 'MIT · TallyUI · MedusaPOS · GitHub · npm'. The only plugin releases are 0.1.0 (2026-10-01) and 0.2.0/0.3.0 (both 2026-10-06), roughly six weeks ago. The demo shows features that 0.3.0 lacks ('Refund at the till … No, not on plugin 0.3.0'; 'On plugin 0.3.0, Order details has no customer note'), so the demo oversells the installable product, though this is disclosed. _[home.desktop.02 footer; text/changelog.txt; text/home.txt demo-vs-own-store table; at-the-till.desktop.02]_

## Overall worst defect per judge

- **J1 First-time visitor** (C2): The home page's demo/own-store table says the demo's only outbound traffic is "anonymous usage events to ph.wcpos.com", without saying who runs wcpos.com. A first-time visitor sees an unexplained third-party domain right where the site is trying to show it can be trusted. _[home desktop slice 02, 'Live demo or your own store' table, row 'Sales reach Vendure, once each, even offline'; home phone 04]_ Fix: Name the owner in that cell, for example "anonymous usage events to our analytics host (ph.wcpos.com, run by WCPOS, the team behind VendurePOS), with no cookie".
- **J2 Working shop owner** (C3): For a shop owner without a developer on hand, refunds are the deal-breaker. On plugin 0.3.0 a refund 'stays Pending until an administrator settles it with two Admin API calls'. The cashier guide's Refund section never says plainly that every refund needs the developer before it leaves Pending. _[home.desktop.02 refund row; at-the-till Refund section]_ Fix: In at-the-till's Refund section, add one plain sentence: 'On your own store each refund shows Pending until whoever runs your Vendure settles it'. Link it to plugin-setup#settle-a-dashboard-refund, and give the freelancer one copy-paste block covering both calls.
- **J3 Developer evaluating it** (C3): A developer maintaining channels with both inclusive and exclusive pricing must guess which store-wide order tax strategy to use. _[Quick start, step 6; shots/quick-start.desktop.03.jpg; text/endpoint_llms_full_txt.txt, 'Why these pairings']_ Fix: State the supported configuration or explicit limitation for mixed-mode channels. Add a verification example comparing receipt and Vendure order tax and grand totals for each pricing mode.
- **J4 Designer** (C5): "What it does today" on the home page mixes two bordered proof cards ("Keeps selling offline", "Every sale lands once") with eight unboxed feature items below them. The second card's short body leaves an empty band above its "Read the 200-send test" button, so the section's two treatments clash and it has a visible hole. _[home.desktop.01]_ Fix: Pick one treatment. Either put the two proof cards in a matched-height row with the action links pinned to the card bottom (flex column, mt-auto) and set the eight features as a uniform 2- or 4-column list under a small subheading, or give all ten items the same unboxed treatment and pull the two proofs out as a separate 'Proof' strip.
- **J5 Competitor-aware sceptic** (C2): A sceptic advising a client can't tell who stands behind this. No maintainer, company or support channel is named, the last plugin release is 2026-10-06, and nothing places it against Shopify POS, Square or Lightspeed or says who should not use it. _[home.desktop.02 footer; text/home.txt; text/changelog.txt]_ Fix: Add a short 'Who builds this / is it for you?' block on home that names the maintainer and links issues/support. Add a three-line not-for list: needs integrated card payments, a cash drawer that opens itself, or iPad tills → Shopify POS or Square. Add a line on release cadence, e.g. the next plugin version and when.
