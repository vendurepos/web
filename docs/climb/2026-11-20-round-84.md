## Worst defect per judge and criterion

### C1 First impression (mean 8.4)
- J1 (8): The first thing above the headline is the pill "Pre-release · plugin 0.3.0", which means nothing to someone who has not yet learned there is a plugin. The hero paragraph runs four lines. What separates "Live demo" from "Quick start" is explained only in the small grey line under the buttons. _[home/desktop/01 hero; home/phone/01]_
- J2 (8): The hero is clear, but the home page's 'Before you start' block mixes counter needs with developer-only lines a shop owner cannot act on: 'Node ^20.19 || >=22.12' and 'your own RxDB Premium licence token (RXDB_PREMIUM)'. On a phone these push 'At the till' (the page for my staff) down to the last paragraph. _[home/desktop/02 and home/phone/04-05, 'Before you start' > 'Setting up the store']_
- J3 (10): none found _[text/home.txt; home desktop and phone screenshots]_
- J4 (8): The hero stacks three text blocks before the product shot: a 4-line subhead (6 lines at 390 px), the button pair, then a further 3-line note 'Your own store needs the plugin on your Vendure server first...'. On a phone the till screenshot only starts near the bottom of the first screen. _[home.desktop.01 hero; home.phone.01]_
- J5 (8): The hero badge says "Pre-release · plugin 0.3.0" as if that were the product's version, but the till you actually use is "till app version 0.1.0", which only the Changelog says. A buyer can't tell from the home page how mature the till itself is. _[home/desktop/01 badge vs changelog/desktop/01 second paragraph]_

### C2 Credibility (mean 8.0)
- J1 (8): The demo row of the comparison table says "All it sends is anonymous usage events to ph.wcpos.com, with no cookie". To a newcomer, a VendurePOS demo sending data to another brand's domain (wcpos) with no word on who that is looks like something being hidden, even though the link explains it one click away. _[home/desktop/02 'Sales reach Vendure, once each, even offline' row; home/phone/04]_
- J2 (8): The home table answers 'Open and close a register with a Z report' with a plain 'Yes' for your own store. Only Limitations and Troubleshooting say that when the store refuses a till update, 'None of those register records reach your Vendure store from this till, so keep the printed Z reports'. _[home/desktop/02 'Live demo or your own store' table vs limitations/desktop/01 last 'At the counter' bullet]_
- J3 (9): none found _[text/home.txt; text/limitations.txt; text/troubleshooting.txt]_
- J4 (8): The comparison table's last row says the demo 'sends ... anonymous usage events to ph.wcpos.com'. That is an unexplained third-party domain (wcpos) on a VendurePOS site, sitting in the same row as the core sync claim. _[home.desktop.02 'Live demo or your own store' table, last row; home.phone.04]_
- J5 (7): No page names who builds or maintains VendurePOS: there is no person, company, support channel or issue tracker beyond a GitHub icon. The one outside party that is named, "ph.wcpos.com", is never explained. All three plugin releases came out between 1 and 6 Oct with nothing since, so a sceptic can't judge whether anyone is behind it. _[home/desktop/02 table row 'Sales reach Vendure' + footer; changelog/desktop/01]_

### C3 Path to a till (mean 8.0)
- J1 (8): Step 3 makes you create two TypeScript script files (src/generate-migration.ts, src/run-migrations.ts). It then offers two more routes in an "Other ways to run the migration" box (npx vendure migrate, the bundled migrations on Plugin setup), so the one step that touches the database has three paths and no clear default for a store made with @vendure/create. _[quick-start/desktop/01-02 step 3]_
- J2 (8): A till set up with the documented 'New POS till key' button gets a role without ReadOrder on plugin 0.3.0, so its order history is refused until someone edits the role by hand. This trap shows up only as a mid-paragraph aside in the optional device-key section and in Connect a till step 1. No step in the main sequence checks for it. _[quick-start text 'Optional: a device key for each till'; connect-a-till/desktop/01 'Give each cashier their own account' step 1]_
- J3 (8): The tax instructions prescribe different store-wide strategies for inclusive and exclusive channels, but tell stores mixing those modes only to 'account for the store-wide strategy', leaving the configuration unresolved. _[quick-start.desktop.03.jpg, step 6; text/endpoint_llms_full_txt.txt:869–895]_
- J4 (8): Step 8 'Sign in and make a sale' and 'Check it worked' are text only: nine lettered sub-steps (a-i) and a five-bullet Dashboard checklist with no image of the sign-in form or of the synced order in the Vendure Dashboard. The reader has no picture of what success looks like. _[quick-start.desktop.03-04; quick-start.phone.07-08]_
- J5 (8): Step 8c sends you off mid-sign-in to add a barcode ProductVariant custom field ("how to add one"). That field needs a second database migration and restart, but the quick start already generated and ran its migration in step 3. Someone who wants scanning has to redo step 3 after the fact. _[quick-start/desktop/03 step 8c; connect-a-till/desktop/01 'Then run a database migration']_

## Overall worst defect per judge

- **J1 First-time visitor** (C2): The home page comparison table says the demo sends "anonymous usage events to ph.wcpos.com". For a first-time visitor, a VendurePOS demo reporting to an unexplained other brand's domain is the one line that makes the site feel like it is hiding something. _[home/desktop/02 table row 'Sales reach Vendure, once each, even offline'; home/phone/04]_ Fix: Say who that is in the same cell, e.g. "to our analytics server (ph.wcpos.com, run by the WCPOS team that builds VendurePOS)", or use a vendurepos.com analytics host.
- **J2 Working shop owner** (C2): The home page's owner-facing comparison tells me my till cannot refund and that 'The refund stays Pending until an administrator settles it with two Admin API calls; see Plugin setup'. That is developer jargon pointing at a developer page. It does not tell a shop owner what actually happens at the counter: hand back cash with Pay out, refund the card on the terminal, ask the person who runs Vendure to settle it. Those practical steps exist only in At the till › Refund a sale. _[home/desktop/02 and home/phone/04, 'Refund a sale at the till' row]_ Fix: Rewrite that cell in shop terms ('No on plugin 0.3.0: refund in the Vendure Dashboard and record cash with Pay out') and link it to /docs/at-the-till#refund-a-sale instead of Plugin setup.
- **J3 Developer evaluating it** (C3): A developer with both tax-inclusive and tax-exclusive channels must guess how to satisfy the conflicting store-wide tax-strategy recommendations. _[Quick start, step 6; quick-start.desktop.03.jpg; text/endpoint_llms_full_txt.txt:869–895]_ Fix: State the supported configuration for mixed pricing modes and how to verify its totals. If that configuration is unsupported, say so explicitly beside the strategy table.
- **J4 Designer** (C5): Inline code across every docs page is padded but its background is nearly invisible on the light theme. Each code token appears to have loose spaces around it ('Run it ( tsx is', 'app.vendurepos.com .', '( pricesIncludeTax: false )'). The code-dense quick start and plugin setup read as sloppy typesetting, and the tall padded tokens also open up line spacing on phones. _[quick-start.desktop.01-03, quick-start.phone.03-06, plugin-setup.desktop.01]_ Fix: Give inline code a visible tinted background (for example a 6-8% foreground mix) with a 1 px border, or drop the horizontal padding to about 0.2em, so the token reads as a chip rather than spaced-out text.
- **J5 Competitor-aware sceptic** (C2): As a sceptic advising a client, I can't tell who stands behind this till. No maintainer, organisation or support route is named anywhere. The only outside domain, ph.wcpos.com, is unexplained. The plugin has had no release since 6 Oct 2026. A shop owner can't judge whether the project will still be maintained in a year, which is the first question anyone asks of a pre-release open-source POS. _[home/desktop/02 footer and demo table row; changelog/desktop/01]_ Fix: Add one line to the home footer and the Overview saying who maintains VendurePOS (and that ph.wcpos.com is theirs), with links to GitHub issues for bugs and support. Also say when the next plugin release is planned.
