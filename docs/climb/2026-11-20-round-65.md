## Worst defect per judge and criterion

### C1 First impression (mean 8.4)
- J1 (8): The hero passes the five-second test, but the 'Before you start' block that follows turns into a developer spec sheet a newcomer cannot parse: 'Node ^20.19 || >=22.12', 'your own RxDB Premium licence token (RXDB_PREMIUM)', 'MySQL, MariaDB and SQLite are not supported', all shown before the closing CTAs. _[home desktop slice 02 / phone slices 04-05, 'Before you start' > 'Setting up the store']_
- J2 (8): The two hero buttons are 'Live demo' and the developer 'Quick start' (npm install, migrations, CORS). The cashier guide 'At the till' (open register, sell, if the internet drops, close the day) only shows up as a text link in the last paragraph of the home page. A shop owner asking whether staff can sell tomorrow gets pointed at server setup first. _[home.desktop.01 hero CTAs; home.desktop.02 final paragraph]_
- J3 (10): none found _[shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (8): Three text blocks stand before the product shot: the subhead 'VendurePOS is an open-source till for Vendure, the open-source headless commerce framework...' runs 4 lines on desktop and 6 on phone, and the note 'Your own store needs the plugin on your Vendure server first...' sits under the buttons, so the demo image is pushed below the fold on phone. _[home.desktop.01, home.phone.01]_
- J5 (8): Home never positions the product against the alternatives a buyer is weighing (Shopify POS, Square, Lightspeed, other open-source tills) and has no explicit 'not for you if…' line; the only positioning is the footer 'For Medusa, see MedusaPOS.' _[home/desktop/01-02 and footer slice]_

### C2 Credibility (mean 8.4)
- J1 (8): The demo row of the comparison table says 'All it sends is anonymous usage events to ph.wcpos.com, with no cookie'. That is a third-party-looking domain the home page never explains (who is wcpos?), so a careful line reads as something being hidden. Only Connect a till says it is a self-hosted PostHog server. _[home desktop slice 02 / phone slice 04, table row 'Sales reach Vendure, once each, even offline']_
- J2 (8): The home page never says who runs app.vendurepos.com or what the hosted till costs. 'Free' only appears in JSON-LD (isAccessibleForFree), and the 'Pre-release · plugin 0.3.0' badge sits next to it with no word on support or pricing. _[home.desktop.01 hero; home.desktop.02 'Before you start']_
- J3 (10): none found _[text/limitations.txt; text/connect-a-till.txt; shots/home.desktop.02.jpg]_
- J4 (9): The plugin-0.3.0 refund caveat is a long sentence crammed into a table cell ('No, not on plugin 0.3.0: refund in the Vendure Dashboard. The refund stays Pending until an administrator settles it with two Admin API calls...'), which breaks the table's scan rhythm. _[home.desktop.02]_
- J5 (7): The live demo is ahead of what anyone can install: 'Refund at the till (live demo only)' and the customer note exist only in the demo, while the installable plugin has been 'plugin 0.3.0' since 2026-10-06 and the changelog admits 'in 0.2.0 and 0.3.0 this role has no ReadOrder', which is still unpatched about 6 weeks later; no maintainer is named, and the demo's 'anonymous usage events to ph.wcpos.com' is not explained on home. _[home/desktop/01 badge + comparison table; at-the-till/desktop/02 'Refund at the till (live demo only)'; changelog text]_

## Overall worst defect per judge

- **J1 First-time visitor** (C2): The home page's own demo row sends the visitor's events to 'ph.wcpos.com' without saying who runs that domain or why it is not vendurepos.com. A first-time visitor who has never heard of VendurePOS meets an unexplained outside domain at the exact moment the site asks for trust. _[home desktop slice 02 / phone slice 04, table cell 'No: the demo store lives in your browser. All it sends is anonymous usage events to ph.wcpos.com, with no cookie']_ Fix: Name the owner in that cell, e.g. 'to our self-hosted PostHog analytics server (ph.wcpos.com, run by the team behind VendurePOS), with no cookie', and keep the link to Connect a till for the event list.
- **J2 Working shop owner** (C1): The home page sends a shop owner to the developer Quick start. The cashier guide (open register, take payment, if the internet drops, close the day) is a text link at the bottom of the page and is hidden behind the chevron in the phone header. _[home.desktop.01 / home.phone.01]_ Fix: Add a third hero button 'A day at the till', or a short card row linking to the At the till sections (open register, take payment, if the internet drops, close the day). Show 'At the till' in the phone header next to Docs and Live demo.
- **J3 Developer evaluating it** (C3): A developer with tax-inclusive and tax-exclusive channels must guess how to reconcile the two recommended tax strategies with the single store-wide setting. _[shots/quick-start.desktop.03.jpg; text/endpoint_llms_full_txt.txt:873-875]_ Fix: Add a mixed-channel case stating the supported configuration and how to verify totals in both pricing modes. If that combination is unsupported, state the limitation explicitly.
- **J4 Designer** (C5): Home 'What it does today' mixes two bordered cards with buttons ('Keeps selling offline', 'Every sale lands once') and eight unboxed text items, so the first two look orphaned and the section has no consistent component. _[home.desktop.01-02]_ Fix: Give all ten features one treatment in a single even two-column grid: drop the borders and buttons from the first two and turn the test links into inline text links inside those items (or box all ten identically).
- **J5 Competitor-aware sceptic** (C2): For someone advising a client, the live demo oversells what can be installed. It refunds at the till and takes customer notes, but the only installable plugin is 0.3.0. That release came out on 2026-10-06 with nothing since. It cannot refund, and its device-key role ships without ReadOrder, a bug the changelog admits but has not patched. The demo looks like a newer product than the one a client would actually run, and no dated 'next release' line says when the gap closes. _[home/desktop/01 ('Pre-release · plugin 0.3.0', Live demo vs your store table); at-the-till/desktop/02 ('Refund at the till (live demo only)'); changelog text]_ Fix: Either ship the plugin release that matches the demo (refund, customer note, ReadOrder in the role) or pin the demo to plugin 0.3.0 behaviour. In both cases, add one dated status line on home, e.g. 'Next plugin release: <date>, adds refunds', with a link to the tracking issue.
