## Worst defect per judge and criterion

### C1 First impression (mean 8.4)
- J1 (8): The hero explains Vendure in jargon: "the open-source headless commerce framework". Someone who only half knows Vendure gets no plain meaning of 'headless', and the badge above the h1, "Pre-release · plugin 0.3.0", starts with a version number before saying what the product is. _[home/desktop/01 hero paragraph and badge; home/phone/01]_
- J2 (8): Lede explains the product as 'open-source till for Vendure, the open-source headless commerce framework' — the owner has to get past 'headless commerce framework' before reading 'keeps selling when the connection drops'; on phone the header shows only Docs and Live demo, with Quick start / At the till hidden behind the chevron _[home.desktop.01 hero lede; home.phone.01 header]_
- J3 (9): none found _[text/home.txt; shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (8): On phone the hero till screenshot is cropped to two product cards, and its category chips are cut off at "Gif", so the product's value barely shows above the fold _[home.phone.01]_
- J5 (9): Home says what it is ('Point of sale for Vendure', 'Pre-release · plugin 0.3.0') and gives the next click, but never says who should not use it or how it compares with a hosted till (Shopify POS, Square, Lightspeed). A buyer weighing options has to work out from 'Before you start' that a shop needing a cash drawer, card-terminal integration or a tested iPad till is better served elsewhere. _[home.desktop.01-02, home.phone.01-05 ('Before you start' block; no 'Who it is not for' or comparison section)]_

### C2 Credibility (mean 8.0)
- J1 (7): Nowhere on the site does it say who makes VendurePOS: the footer gives only "MIT licensed. Built with TallyUI". Yet the home comparison table says the demo sends "anonymous usage events to ph.wcpos.com", another brand's domain that the home page never explains. Even Connect a till only calls it "a self-hosted PostHog analytics server" and never says whose it is. _[home/desktop/02 'Live demo or your own store' table, last row; footer; connect-a-till 'Where requests go']_

- J3 (9): none found _[text/home.txt; text/limitations.txt; text/connect-a-till.txt]_
- J4 (9): The comparison table's "Refund a sale at the till" cell is a 4-line caveat while its neighbours are one or two words. It is honest, but the row looks heavy and lopsided _[home.desktop.02]_
- J5 (7): The live demo sells features the shippable plugin lacks. The home table says refunds are 'Yes' on the live demo but 'No, not on plugin 0.3.0' on your own store, and at-the-till says 'On plugin 0.3.0, Order details has no customer note. On the live demo…'. To a sceptic that reads as a demo that runs ahead of a stalled package. _[home.desktop.02 ('Live demo or your own store' table); at-the-till.desktop.01 (Order details note); changelog.desktop.01 / changelog.phone.01 (release dates, ReadOrder note)]_

## Overall worst defect per judge

- **J1 First-time visitor** (C2): A stranger can't tell who is behind VendurePOS: no maker, company or person is named anywhere. The only outside party the home page shows is an unexplained 'ph.wcpos.com' receiving demo usage events, which makes a newcomer wonder whose project this is and where their data goes. _[home/desktop/02 comparison table last row and footer ('MIT licensed. Built with TallyUI.')]_ Fix: Add one footer line naming who builds and maintains VendurePOS (with a link). Where ph.wcpos.com appears, say in a few words that it is that maker's own self-hosted analytics.
- **J2 Working shop owner** (C2): On a real store (plugin 0.3.0) a refund cannot be done at the till, and the site explains it as an administrator settling it 'with two Admin API calls' while the live demo refunds at the till — an owner cannot tell how a customer refund works day to day or what the customer is told _[home.desktop.02 'Live demo or your own store' row 'Refund a sale at the till'; at-the-till 'Refund a sale']_ Fix: In the home row and At the till › Refund a sale, say in plain words who does the refund, where (Vendure Dashboard), and when the customer's money actually goes back; mark the demo's refund-at-till as 'demo only, not on 0.3.0 stores'; link Plugin setup for the developer steps instead of naming API calls
- **J3 Developer evaluating it** (C3): A developer with both tax-inclusive and tax-exclusive channels must guess how to satisfy the two prescribed tax-strategy pairings using one store-wide setting that also affects the web shop. _[shots/quick-start.desktop.03.jpg; text/endpoint_llms_full_txt.txt, Quick start step 6]_ Fix: Add explicit guidance for mixed-pricing channels: state the supported configuration or clearly identify the unsupported combination, with a concrete totals check before enabling live sales.
- **J4 Designer** (C6): On phone, inline code chips wrap in the middle of a token. "packages/vendure-/plugin/CHANGELOG.md" splits, and "tallyResolveNeedsAdmin(commandId, applied | rejected, note)" breaks into two ragged chips. The changelog and the chip-heavy docs paragraphs look broken at 390 px _[changelog.phone.01, changelog.phone.03]_ Fix: Give inline code white-space: nowrap, and allow overflow-wrap: anywhere only for tokens wider than the column. Move long signatures and paths such as tallyResolveNeedsAdmin(...) into fenced code blocks or plain prose
- **J5 Competitor-aware sceptic** (C2): The live demo shows refunds at the till and an order customer note that plugin 0.3.0 cannot do ('Refunds … No, not on plugin 0.3.0'; 'On plugin 0.3.0, Order details has no customer note. On the live demo…'). All three plugin releases came within six days, the last on 2026-10-06, and none has shipped since, while a known role bug ('this role has no ReadOrder … Not in the release notes') is still in the current release. A competitor-aware adviser would warn a client that the demo overstates what they can install today and that the package may have stalled. _[home.desktop.02 ('Live demo or your own store' table); at-the-till.desktop.01; changelog.desktop.01]_ Fix: Ship a plugin release that closes the gap (refunds at the till, customer note, ReadOrder in the device-key role), or make the demo run plugin 0.3.0 and label demo-only features inside the demo. Also show 'last plugin release: <date>' plus a short roadmap line on home, so the release gap reads as planned work rather than abandonment.
