## Worst defect per judge and criterion

### C1 First impression (mean 8.4)
- J1 (8): The hero is clear, but the home page's 'Before you start' block, which a newcomer reads before any closing next step, switches into developer config jargon: 'Node ^20.19 || >=22.12', 'one tab per till and not a private window', 'your own RxDB Premium licence token (RXDB_PREMIUM)'. A visitor who only half knows Vendure can't parse it. _[home/desktop/02 'Before you start' (also home/phone/04-05)]_
- J2 (8): The hero offers only 'Live demo' and 'Quick start'; the line under it, 'Your own store needs the plugin on your Vendure server first…', is aimed at developers, and the cashier guide 'At the till' is not offered from the hero. On phone it sits behind an unlabeled chevron in the header. _[home.desktop.01 / home.phone.01]_
- J3 (10): none found _[shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (8): At 390 px the hero lede runs six lines and a three-line note ('Your own store needs the plugin…') follows the buttons, so the till screenshot starts below the first screen _[home phone 01]_
- J5 (8): The hero ('Pre-release · plugin 0.3.0', 'Point of sale for Vendure', Live demo / Quick start) is clear, but nowhere on the home page does it say who builds or supports VendurePOS, who it is NOT for (e.g. stores needing card-terminal integration, cash drawers or Safari tills), or how it compares with Shopify POS, Square or Lightspeed. The 'What it does today' section is ten equal grey cards with no ranking, so the strongest proof (25-sale / 20-offline acceptance test, 200-send test) is buried among routine features. _[home.desktop.01-02; text/home.txt 'What it does today']_

### C2 Credibility (mean 8.2)
- J1 (8): The home comparison table says the demo 'sends anonymous usage events to ph.wcpos.com' without saying who wcpos.com is. An unexplained third-party domain on a VendurePOS page makes a newcomer wonder who is behind the product. Separately, 'MIT licensed' next to 'you need your own RxDB Premium licence token' reads as a catch unless it is explained. _[home/desktop/02 table row 'Sales reach Vendure, once each, even offline'; 'Before you start' bullet 6]_
- J2 (9): Device support is vague: 'Its browser tests run in desktop Chrome; other browsers are not tested yet.' leaves an owner unsure whether a tablet or iPad works at the counter. _[limitations.desktop.01 / home.desktop.02 'Before you start']_
- J3 (10): none found _[text/home.txt; text/limitations.txt; text/troubleshooting.txt]_
- J4 (8): The comparison row 'Sales reach Vendure, once each, even offline' says the demo sends 'anonymous usage events to ph.wcpos.com'; an unexplained wcpos.com domain on a VendurePOS site reads as another brand _[home desktop 02, 'Live demo or your own store' table]_
- J5 (6): The hero framing says open source and the footer says 'MIT licensed', yet 'Before you start' admits that to 'build and host it yourself instead of using app.vendurepos.com, you need your own RxDB Premium licence token (RXDB_PREMIUM)', which is a paid dependency. It never says whether hosted app.vendurepos.com is free, who runs it, or what happens if it goes away. The site also names no maintainer and no support channel, and the demo's 'anonymous usage events to ph.wcpos.com' is unexplained on home (wcpos is never introduced). The changelog shows plugin 0.2.0 and 0.3.0 shipped the same day, 2026-10-06, then nothing for six weeks, despite a known bug: 'in 0.2.0 and 0.3.0 this role has no ReadOrder, so the till's order history is refused until you add it to the role'. _[home.desktop.02 'Before you start'; home footer; changelog.desktop.01; text/changelog.txt]_

## Overall worst defect per judge

- **J1 First-time visitor** (C1): After a clear hero, a first-time visitor scrolling the home page meets dense developer detail: a semver Node range, an RXDB_PREMIUM env var, a 'refund stays Pending until it is settled' caveat and an unexplained ph.wcpos.com. Nothing restates the simple choice, try the demo or set up your store, so a half-informed visitor is more likely to leave than click. _[home/desktop/02 ('Live demo or your own store' table and 'Before you start'); home/phone/04-05]_ Fix: Cut 'Before you start' on the home page to three plain lines (Vendure 3.6+ on Postgres, a browser at the counter, pre-release) and link the rest to Quick start and Limitations. End the page with the Live demo / Quick start buttons again.
- **J2 Working shop owner** (C2): The site never says plainly which counter devices the till supports. The only line is 'Its browser tests run in desktop Chrome; other browsers are not tested yet.', so a shop owner can't tell whether staff can sell on a tablet or iPad tomorrow. _[limitations.desktop.01 / home.desktop.02 'Before you start']_ Fix: Add one line to 'Before you start' and to Limitations naming the devices and browsers known to work at the counter (e.g. 'Tested: Chrome on a Windows or Mac PC. iPad Safari and Android tablets: not tested yet'), so owners know what hardware to use.
- **J3 Developer evaluating it** (C3): A developer maintaining both tax-inclusive and tax-exclusive channels is warned that tax strategy is store-wide but is not told which configuration to use or how to verify both modes. _[Quick start, step 6, 'Why these pairings'; text/endpoint_llms_full_txt.txt, lines 832–860]_ Fix: Document the recommended configuration for mixed-pricing channels and provide a tax-total verification example for each mode. If that combination is unsupported, state the limitation explicitly.
- **J4 Designer** (C5): The home 'What it does today' section is ten equal-weight grey-on-grey cards in a 2-column grid with barely visible card edges, so the two proven claims (offline, lands once) carry the same visual weight as minor features and the section reads as one flat block _[home desktop 01–02 / phone 02–03]_ Fix: Promote the two proven claims (sells offline, each sale lands once) to a distinct featured row with their test links; render the other eight as a compact 3–4-column grid or borderless list with icons; give cards real contrast (white fill or a visible border on the grey page)
- **J5 Competitor-aware sceptic** (C2): The till is sold as open source ('MIT licensed'), but self-hosting requires a paid RxDB Premium licence. That appears only as a 'Before you start' bullet, and the site never says who runs the hosted app.vendurepos.com, whether it stays free, or who maintains the project and where to get support. A sceptic advising a client reads this as 'free only while someone else's hosted app exists', and the six-week silence since plugin 0.3.0 with a known unpatched ReadOrder role bug reinforces it. _[home.desktop.01-02 (hero, 'Before you start', footer); changelog.desktop.01]_ Fix: Directly under the hero, add one plain line: 'The till app is MIT; the hosted till at app.vendurepos.com is free [state terms]; self-hosting needs a paid RxDB Premium licence.' Add a 'Who maintains this / support' line with a real channel. Ship 0.3.1 so the 'New POS till key' role includes ReadOrder, or say in the changelog when it will.
