## Worst defect per judge and criterion

### C1 First impression (mean 8.4)
- J1 (8): The hero is clear, but the home page's 'Before you start' block falls into developer jargon a first-time visitor cannot use to decide anything: 'Node ^20.19 || >=22.12', 'your own RxDB Premium licence token (RXDB_PREMIUM)', and in the comparison table 'settles it with two Admin API calls'. _[home.desktop.02 'Before you start' and 'Refund a sale at the till' row; home.phone.04-05]_
- J2 (8): The hero explains Vendure as a 'headless commerce framework', which means nothing to a shop owner. On the phone the top bar offers only 'Docs' and 'Live demo', so 'what happens when the internet drops' takes scrolling to find. _[home.desktop.01 hero subline; home.phone.01 header]_
- J3 (10): none found _[text/home.txt; shots/home.desktop.01.jpg; shots/home.phone.01.jpg]_
- J4 (8): The hero lede runs long under 'Point of sale for Vendure', and a helper line sits between the Live demo/Quick start buttons and the screenshot, so the eye has three text layers to read before it reaches the product image _[home.desktop.00 hero]_
- J5 (8): The hero ('Point of sale for Vendure', Live demo / Quick start) is clear, but nothing on the page says who builds VendurePOS. The only provenance is the footer 'Built with TallyUI. For Medusa, see MedusaPOS.', which is never explained. _[home.desktop.01 hero; home.desktop.02 footer]_

### C2 Credibility (mean 8.4)
- J1 (8): The home table says the demo 'sends ... anonymous usage events to ph.wcpos.com' but nothing on the home page says what wcpos is or who makes VendurePOS, so an unknown third-party domain shows up with no explanation. Only Connect a till says it is a self-hosted PostHog server. _[home.desktop.02 'Sales reach Vendure, once each, even offline' row; home.phone.04]_
- J2 (8): The comparison table says the live demo refunds at the till ('Refund a sale at the till | Yes'). On plugin 0.3.0 a real store cannot do this: the refund goes through the Vendure Dashboard and 'stays Pending until an administrator settles it with two Admin API calls'. That limit is easy to miss next to the demo's 'Yes'. Smaller point: the demo shots show 'Last synced 10:06 PM' next to 'open since 22:06', two time formats in one screen. _[home.desktop.02 / home.phone.04 comparison table; at-the-till 'Refund a sale']_
- J3 (10): none found _[text/home.txt; text/limitations.txt; text/connect-a-till.txt]_

The one quibble is the changelog note 'Released the same day as 0.2.0, a few hours later.', which reads like housekeeping rather than information _[changelog]_

## Overall worst defect per judge

- **J1 First-time visitor** (C1): After a clear hero, the home page asks a first-time visitor to read installer-level detail ('Node ^20.19 || >=22.12', 'RxDB Premium licence token (RXDB_PREMIUM)', refunds settled 'with two Admin API calls'). That makes the product look harder and less finished than it is, at exactly the moment the visitor is deciding whether to stay. _[home.desktop.02 'Live demo or your own store' table and 'Before you start'; home.phone.04-05]_ Fix: Shrink 'Before you start' to one plain line ('Needs Vendure 3.6+ on Postgres and our server plugin — see the quick start'), shorten the refund row to 'No, refund in the Vendure Dashboard for now', and leave the Node range, RXDB_PREMIUM and Admin API detail to the docs.
- **J2 Working shop owner** (C2): On plugin 0.3.0 staff cannot refund at the till: refunds go through the Vendure Dashboard and stay Pending until an administrator makes 'two Admin API calls'. Yet the home comparison table shows 'Refund a sale at the till | Yes' for the live demo, so an owner trying the demo will expect refunds to work at their own counter tomorrow. _[home.desktop.02 / home.phone.04 comparison table; at-the-till 'Refund a sale']_ Fix: Label the demo cell 'Demo only — not on plugin 0.3.0'. Add a one-line 'Refunds: not at the till yet — done in the Vendure Dashboard by whoever runs your store' to the home 'Before you start' list, and give the at-the-till refund section a plain-language workaround for staff (Pay out the cash, note the order number) instead of a link to Plugin setup.
- **J3 Developer evaluating it** (C3): A developer with tax-inclusive and tax-exclusive channels must guess how to reconcile the two prescribed strategies with the single store-wide setting. _[text/quick-start.txt, step 6, 'Why these pairings'; shots/quick-start.desktop.03.jpg]_ Fix: State whether mixed pricing modes are supported. If supported, document the tested strategy and concrete checks for both channel modes; otherwise state that limitation explicitly.
- **J4 Designer** (C5): The at-the-till figures render at three unrelated widths (~836 px full column, ~418 px centred in a nested padded frame, ~546 px) with different frame treatments, so the docs' one illustrated page looks assembled rather than designed _[docs/at-the-till, desktop slices showing the payment, cashier sheet and closure figures]_ Fix: Give every doc figure one component: full content width (or one fixed max-width such as 640 px, centred), the same 1 px border and radius, and no inner padded frame. Crop narrow phone-layout captures to a consistent aspect ratio, or pair them side by side, instead of shrinking them inside a wide card.
- **J5 Competitor-aware sceptic** (C2): A consultant comparing this with Shopify POS, Square or a WooCommerce till finds nothing on the site that says who maintains VendurePOS or how active it is. The footer names only 'MIT licensed. Built with TallyUI. For Medusa, see MedusaPOS.', ph.wcpos.com appears unexplained, and the changelog's last release is 6 Oct 2026. There is also no plain 'who should not use this' section, so the persona can't tell a maintained pre-release from an abandoned toy. _[home.desktop.02 (footer and comparison table); changelog.txt]_ Fix: Add a short 'Who's behind it / project status' line to home: the maintainer, release cadence and a link to recent repo activity. Next to it, add a 'Not for you if…' box (needs Postgres and Vendure 3.6+, desktop Chrome only, no card-terminal or cash-drawer integration).
